100 MB/file, 10 GB/project (both raisable; 40 GB grants are routine for large projects). 20 project creations/hour/user, 10/day/organization, 40/hour/IP (warehouse config.py defaults). Files cannot be uploaded to a release older than 14 days (MAXIMUM_AGE_FOR_NEW_UPLOADS). Deleting a file frees quota; yanking does NOT.

Per-object capBy default, PyPI limits the size of individual files to 100.0 MB (200.0 MB for projects owned by an organization). (100000000 bytes)
Retention| Deletion is permanent and irreversible ('cannot be undone without administrative intervention')
Interfacerest, rclone rest
ToolingLegacy upload API POST /legacy/ (twine), JSON API GET /pypi/<name>/json for metadata, direct file GET from files.pythonhosted.org. Orgs/teams exist. Named wrapper class: pypi/* tools, twine, and warehouse itself. No rclone backend.
Composes withProjects owned by an organization get higher defaults of 200.0 MB per file and 20.0 GB per project; a project that leaves an organization goes back to the personal defaults.
ReliabilityDeletion is permanent and irreversible ('cannot be undone without administrative intervention'). Releases are append-only in practice but files can be deleted to free project quota, so unlike npm this is not immutable-by-design. Treat it as stable-but-deletable. Quota enforcement is a hard 400 at upload, so budget against the 10 GB project figure.
Notes100 MB per file, 10 GB per project. Both are defaults, both are raisable by filing a GitHub issue. Unlimited number of projects. Verified in warehouse source: MAX_FILESIZE = 100 * ONE_MIB, MAX_PROJECT_SIZE = 10 * ONE_GIB, UPLOAD_LIMIT_CAP = 1 GiB.
