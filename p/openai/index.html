Toolingopenai-python, openai-node, curl; purpose field selects the lifecycle class
Composes with2,000 projects/org x 2.5 TB = nominally 5 PB per org. Files are project-scoped and cannot be moved between projects, so a pooler must track (project -> file_id). Because purpose=batch and purpose=vision are both uploadable AND downloadable, they are the only two classes usable as actual storage.
ReliabilityREAD GATE IS PER-PURPOSE, NOT PER-ACCOUNT. An OpenAI staff-adjacent answer on the developer forum gives the directionality table: assistants up/NO down; user_data up/NO down; fine-tune up/NO down; evals up/NO down; batch up/YES down; vision up/YES down; *_output down only. So purpose=user_data and purpose=assistants are write-only. Uploading there is data loss. Storage is genuinely free (no per-GB-day charge for raw files; the $0.10/GB-day on the pricing page is vector store storage, not Files API storage). Identity: ChatGPT signup is email-only, but generating the FIRST API key now mandates phone verification (SMS or WhatsApp, one number reusable 3x, rolled out to a listed set of countries). That is the binding constraint here.
