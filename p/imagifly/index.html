The free plan runs the standard queue at 2 concurrent tasks and keeps images and videos for 2 days. Limits
  • volume-quota (binding) 10 credits a day on the free plan, granted on each day the account visits ('10 credits on each day you visit'); the pricing page prices 1,200 credits as 'Approx. 400 images with GPT-Image-2.6', which is 3 credits an image, so the daily grant is about three images of that model source
  • retention-clamped the free plan keeps images and videos for 2 days ('图片和视频保留 2 天'), against 5 days on Plus and Pro and 15 days on Max source
the free plan's standard queue runs 2 concurrent tasks ('标准队列（2 个并行任务）') and a request above the plan's concurrency returns 429 CONCURRENCY_LIMIT; a request that the balance cannot cover is rejected with 402 before any work starts
Bindingvolume-quota 10 credits a day is about three GPT-Image-2.6 images, so the allowance is spent before any concurrency or rate limit binds, and the 2-day retention then discards the output
Identityemail the daily 10 credits are granted 'while signed in' and an API key is created in the console after signing in ('Open the API console, sign in, and click Create'); the pages state 'no credit card required'; no sign-up form is published and the sign-in dialog is rendered client-side, so an email address is the default assumption rather than a read value, and whether the generator accepts an anonymous request is not stated
Egressnot published: the output arrives as a URL on imagedelivery.net and no download quota, egress allowance or price per TB is stated on the pages read
Per-object capnot applicable: the unit is a generation, not a stored object; the API accepts one image per request ('One image per request: imageCount is always 1') and returns a temporary delivery URL
Retentionthe free plan keeps images and videos for 2 days ('图片和视频保留 2 天'), against 5 days on Plus and Pro and 15 days on Max; the API docs say to treat the output URLs 'as temporary delivery links rather than permanent storage' (2 days)
Interfacerest, cli a documented JSON API at https://imagifly.net/api/v1 authenticated with 'Authorization: Bearer imf_...' or 'x-api-key', an MCP server, and the npm CLI @imagifly/cli; the web app needs no client
endpoint: https://imagifly.net/api/v1
Toolinga documented REST API, an MCP server and the npm CLI @imagifly/cli; the site itself is an open-source Next.js front end over ComfyUI API endpoints (LastLighter/Dreamifly) that a user could run on a rented or free machine, listed last because the hosted service above needs no machine
Composes withcomposes as an image and video generator behind a polling loop: a submit returns 202 with a task id and there is 'no webhook, callback or push channel', so the caller polls every 2-5 seconds; the free 10 credits a day is about three GPT-Image-2.6 images, so it cannot carry a batch
Reliabilitythe Dreamifly-era page warned that generation may take a long time and that an occasional failed image is normal ('图片生成可能耗时较长，偶尔一张图片出错是正常情况'); the API returns the credits of a failed task automatically and does not refund a successful one
NotesThe compute is the vendor's, not the user's: the user buys generations and never gets a machine or a GPU-hour. The name Dreamify AI is the free-compute directory free.waxianzhi.com's label for the site at dreamify.slmnb.cn, which branded as Dreamifly and said its images ran on the idle RTX 4090 cards of 30 home computers, free and unlimited (archived 2025-11-01). On 2026-11-06 dreamify.slmnb.cn/zh answered HTTP 404 and dreamifly.com answered 301 to imagifly.net, whose project homepage is imagifly.net, and the Dreamifly project's own homepage field is imagifly.net, so the current site is the successor brand of the Dreamifly site; it grants 10 credits a day rather than an unlimited pool and no longer says which GPUs serve the models. Not established: whether an account can be created without an email address, whether an anonymous generation is accepted, and whether the 4090 pool still serves any model.
