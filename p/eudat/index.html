10 GB per file, 20 GB per record. So 20 TB needs ~1,024 records, which trips EUDAT's 'fair share' clause: 'the uploading of large number of files or creating large number of records is not considered fair use' and they ask you to contact them first. Live rate limit header: x-ratelimit-limit: 500, x-ratelimit-remaining: 499.
Identityemail a B2SHARE account is a B2ACCESS account: B2SHARE's own login page offers only "Sign in with B2ACCESS", and B2ACCESS registers either a home-organisation identity over eduGAIN, a social identity, or a local account. The local-account form asks for a user name, a password entered twice and an email address; organisation name, common name and comments are optional. No card and no phone number is asked for.
EgressFree, unmetered, direct per-file content URLs (GET /api/records/<id>/files/<name>/content). No egress terms or pricing exist; EUDAT is publicly funded.
Per-object cap10 GB per file (10000000000 bytes)
Retentiona permanent service; if it draws to a close, data stays archived and accessible for at least 2 years and is migrated to other suitable repositories
Interfacerest, rclone rest
ToolingInvenioRDM-style REST API (live: GET /api/records?size=1 -> 200 with hits/entries and per-file content links); OAI-PMH; DOI minting (10.23728). Python client via plain requests. No rclone backend.
Composes with20 GB per record x unlimited records. 50 records = 1 TB; 1,000 records = 20 TB in one account. The docs state outright 'There is no limit to the number of files you can deposit or records you can create'.
ReliabilityRate-limited at 500 requests/window and watched for bulk growth; EUDAT says it 'will increase back-end storage capacity incrementally when necessary', which implies throttling rather than deletion, but the fair-share clause is the trigger for manual review.
