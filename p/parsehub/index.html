No limit on the length of one run is stated: a ParseHub blog post lists the limits of its plans as projects, pages per run and speed. The 40 minutes on the pricing page is the Free speed, one worker at approx. 5 pages a minute collecting 200 pages in that time, and the Standard and Professional columns give the same row as 10 minutes and under 2 minutes beside 10,000 and unlimited pages per run, so the row reads as a speed and not a run-length cap. Third-party reviews report a 40-minute limit on one Free run. Whether a Free run is stopped at a wall-clock time is unverified: behind a sign-up.
Bindingrequest-rate 5 pages a minute bounds a Free account at 7,200 pages a day however many runs are queued; the 200-page run cap only forces a large crawl into many runs
Identityemail no credit card is required to sign up; the sign-up form posts a name, an email address and a password, and the sign-up code carries an email-verification screen
Egressnot applicable: run data downloads as CSV or JSON
Per-object cap200 pages per run on Free (10,000 on Standard, unlimited on Professional); a results file over 10 MB is not saved as CSV, only as JSON
Retentionrun data is kept for 14 days on Free and Standard, 30 days on Professional (14 days)
Interfacerest REST API v2 under https://www.parsehub.com/api/v2/ with an api_key parameter from the account page: start a run of a project on the ParseHub cloud, poll the run, and fetch its data as csv or json (always gzip-encoded); the desktop application for Mac, Windows and Linux builds projects by point and click; the Account Settings tab of the account page shows the key, and the page code renders that field with no condition on the plan; whether a signed-in Free account is issued a non-empty key is unverified: behind a sign-up
Toolingthe ParseHub desktop application (Mac .dmg, Windows installer, Linux AppImage) builds projects; runs execute on ParseHub servers; the REST API starts runs and fetches data
Composes withBuild a project once in the desktop application, then start runs and pull JSON over the REST API from any scheduler, since scheduling is a paid feature; Free projects are public, so their designs and run data may be shared with other users
Reliabilitya results file over 10 MB is not saved as CSV: the CSV download comes back empty with a notice and only the JSON holds the data
NotesConfirmed as a no-code scraper with a free plan. Free runs: no run count is stated; a project can be run many times, runs past the speed limit queue, and Free holds up to 100 queued runs. Pages per run: 200 on Free (10,000 on Standard at USD 189 a month, unlimited on Professional). Export formats: CSV (opened as Excel) and JSON from the desktop application, the website or the API. The desktop application only builds projects; runs execute on ParseHub servers, so no machine has to stay on. The caveats are that Free projects are public and run data is kept 14 days.
