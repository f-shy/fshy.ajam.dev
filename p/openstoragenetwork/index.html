The ACCESS documentation states it as a 10-50 TB project allocation with '1 ACCESS credit = 1 GB' and 'Campus Champions may request 1 TB for testing'. Per-object-cap: not documented; the counted limit is 'up to 1.6 million files' per allocation. Retention: 'Never purged', 'Not backed up' (support.access-ci.org resource table). Genuinely indefinite, which is unusual in this niche. request-rate: not published, but the docs note parallel requests against the inside endpoints spread across OSDs 'and therefore achieve very large training throughput'. Gate: ACCESS allocation review an Explore project is a 1-page proposal, reviewed, and the PI needs an institutional email.
Identityinstitution (inferred, not read) not published
EgressFree and unmetered. This is NSF-funded infrastructure, there is no egress meter anywhere in the docs. Public buckets are readable anonymously, which is the fetch path.
RetentionRetention: 'Never purged', 'Not backed up' (support.access-ci.org resource table). Genuinely indefinite, which is unusual in this niche.
Interfaces3, rclone, cli s3
Toolingrclone with provider = Ceph, aws cli, Cyberduck, restic. Endpoints are per-pod, e.g. https://mghp.osn.xsede.org. Bucket management is via the Coldfront portal (coldfront.osn.mghpcc.org), not the CLI.
Composes withThe multiplier is ACCESS projects, not buckets: 'one project can have many S3 Buckets as long as the total quota doesn't exceed the project network quota'. So 50 TB per ACCESS project. ACCESS allows 'Multiple requests allowed' for Explore, Discover and Accelerate project types, with credit limits of 400,000 / 1,500,000 / 3,000,000 respectively. At 3,000 credits per TB of OSN, a single Explore project (400k credits) can fund ~133 TB if it were all spent on OSN, well above the 50 TB per-project cap, meaning the per-project cap is the binding limit and multiple projects is the way past it.
ReliabilityBuckets are 'not backed up' and are created by ticket/portal form, not API. Automation is limited to reads and writes, not bucket provisioning.
