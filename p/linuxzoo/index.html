ReliabilityThe site's own front page carries a live 'Status: Stable' line and also the notice 'Patching and rebooting underway', so the service is maintained but not always up; the operator states it is a privilege rather than a right and that response time may be long.
NotesClassified as a rejection on egress, not on money or identity: it is free, it needs only an email, and it gives root. The disqualifier is explicit and repeated on the vendor's own page: 'no outgoing traffic is supported'. That makes it a lab for learning Linux, which is what it says it is, and not a machine for a stack. A second constraint is the control-panel reap: the VM dies within minutes if no browser window is showing a control panel, so it cannot run unattended even inside the two-hour window. The per-VM shape is unpublished. The front page showed a transient 'Having a disaster' error block on the same read, so the service is live but rough.
Evidence notedocumented The no-egress rule, the queue, the 10-minute to 2-hour window, the control-panel reap, the node count and the email requirement are all quoted from linuxzoo.net's own technical and how-to pages read. The per-VM vCPU, RAM and disk allocation is not published on any page read; only the host nodes' totals are.
