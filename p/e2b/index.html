The 1-hour continuous runtime is the headline difference between Hobby and the USD 150 a month Pro plan, so the time cap is a plan gate rather than a technical ceiling. It resets on pause and resume.
Bindingretention-clamped One hour of continuous runtime per session is the constraint that decides the row: no arrangement of the credit produces a machine that is up for a month, only 604 one-hour sessions.
Identityemail The console signup form asks for 'E-Mail', 'Name' and 'Password', or a social provider; no phone and no card field. The pricing page states 'No credit card required to start' but adds 'Some accounts are asked to verify with a one-time $5 card payment to help prevent abuse. The $5 is added to your project as usage credits and is non-refundable.'
EgressNo egress charge or allowance is stated on the pricing page; sandbox storage is stated free and the page prices CPU and RAM only. Outbound traffic leaves from ephemeral rotating IPs with no published CIDR list.
Per-object capSandboxes can be configured with 1 to 8 vCPUs and 1 to 8 GiB of RAM; the default sandbox has 2 vCPUs and 4 GiB. Storage is 10 GiB on Hobby.
RetentionSandbox storage is included with every plan at no extra cost; a paused sandbox keeps its filesystem and its memory. 'Paused sandbox retention: Unlimited' on every plan.
Interfacerest, cli SDK (Python, JavaScript) over a REST API; Sandbox.create() plus pause and resume
Toolinge2b Python and Node SDKs; templates; sandbox pause and resume
Composes withpause keeps memory, so a long agent run resumes mid-process rather than replaying its setup
ReliabilityA sandbox that hits the one-hour limit loses in-memory state unless it was paused or snapshotted first; the default timeout when none is set is 5 minutes. Some accounts are asked for a one-time $5 card verification before they can start.
NotesArithmetic, recomputed today: 2 vCPU x USD 0.0504 + 4 GiB x USD 0.0162 + 0 storage = USD 0.1656 an hour. USD 100 / 0.1656 = 603.9 h = 25.2 days at 24/7, and a 730-hour month would cost USD 120.89. But those 604 hours cannot be taken as a continuous machine: Hobby caps continuous runtime at 1 hour, so they are 604 sessions of one hour or less, and the credit is the smaller constraint only in the sense that it runs out second. At the maximum shape, 8 vCPU / 8 GiB, the hour is USD 0.5328 and USD 100 buys 187.7 h = 7.8 days, still in one-hour slices. GPU trap: not applicable, because E2B states it sells no GPU at all, so there is no advertised product the credit fails to cover. The real catch is the card AFTER the credit, not before: 'If you have no payment method, every project in your workspace is blocked shortly afterwards. Add a payment method to continue using E2B.' That is a hard stop at the end of the USD 100 with no free path onward. Pausing is unlimited and free, so a paused sandbox can sit indefinitely, but it is not running. One conflict to note: the billing docs' cost advice says the default is '2 vCPU, 512 MiB RAM' while the pricing page says 4 GiB; if 512 MiB is right the hour is USD 0.1089 and the credit buys 918 h, so the shape should be checked in the console before trusting either figure.

The one conflict is the default sandbox RAM, 4 GiB on the pricing page against 512 MiB in the billing docs' cost advice; the 4 GiB figure is used because it is the one the pricing page states as the default shape.

Free tierE2B Desktop runs on the E2B Sandbox plan: Hobby is USD 0 a month with a one-time USD 100 in usage credits, up to 10 concurrently running sandboxes and up to 1 hour of continuous runtime per sandbox; no credit card is required to start, though some accounts are asked to verify with a one-time USD 5 card payment.
unit credits; metered on wall-clock; The SDK docs state the Desktop Sandbox is built on top of E2B Sandbox, so the same account, credits and per-second CPU/RAM rates apply; no separate Desktop price is published.

Limits

Continuous runtime resets on pause and resume; a paused sandbox is not billed and does not count toward the concurrency limit.
Bindingretention-clamped The Hobby one-hour continuous runtime cap ends a desktop session first at sustained use; the USD 100 credit is one-time and larger, and pausing resets the clock.
Identityemail The E2B console sign-up page renders 'Sign up with your email and a password or a social provider' with E-Mail, Name and Password fields; the pricing page states 'No credit card required to start', with an optional one-time USD 5 card verification for some accounts that is added to project credits.
EgressNo egress charge or allowance is stated; the pricing page bills CPU and RAM per second and states sandbox disk is included at no extra cost.
Per-object capThe desktop sandbox is an Ubuntu 22.04 environment with an XFCE desktop; a create example sets resolution 1024x720 at 96 dpi. The E2B plan table states up to 8 vCPUs and 10 GiB of sandbox disk on Hobby, with 1 to 8 vCPUs and 1 to 8 GiB of RAM configurable.
RetentionPaused sandbox retention is unlimited on every plan: a paused sandbox keeps its filesystem and memory with no time-to-live and no automatic deletion; the default timeout is 5 minutes and on timeout the sandbox is killed unless onTimeout is set to pause.
Interfacerest, cli, browser The @e2b/desktop (npm) and e2b-desktop (pip) SDKs expose mouse, keyboard, screenshot and VNC streaming on a Linux desktop; E2B Surf is an open-source computer-use agent using it.
endpoint: https://api.e2b.dev
Toolingnpm i @e2b/desktop or pip install e2b-desktop; sandbox.stream.start() gives a browser-viewable VNC URL; E2B provides Python, JavaScript and TypeScript SDKs and a CLI.
Composes withThe desktop sandbox shares one E2B account and its USD 100 credits with the ordinary code sandbox, so an agent can switch between shell work and computer use while drawing on the same one-time balance.
ReliabilityThe default timeout is 5 minutes and the default on-timeout action is kill, which loses in-memory state; a stream may drop after about an hour because of load-balancer drains even while the sandbox keeps running, so clients reconnect.
NotesE2B Desktop is a graphical variant of the same hosted E2B Sandbox, not a separately priced product: its SDK creates a desktop sandbox with mouse, keyboard, screenshot and VNC streaming against the same API key and the same USD 100 one-time Hobby credit. At the default 2 vCPU / 4 GiB shape the published rates give USD 0.1656 per running hour, so the credit buys about 604 one-hour-or-shorter sessions. Hobby caps each session at one hour of continuous runtime; pausing resets it and is free. The existing compute/e2b record covers the same plan for code sandboxes; this record is the desktop computer-use tier.
Evidence notedocumented The Desktop SDK, its dependence on E2B Sandbox and the computer-use flow are quoted from the vendor docs and PyPI page read on 2026-11-25; prices, limits and signup gate are from the vendor pricing and billing pages on the same date.
