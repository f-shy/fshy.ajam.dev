Limits
  • write-gated (binding) every registration and every later change is a pull request that a maintainer reviews; the service states it can deny any request for any reason, and review time is volunteer time with no published figure source
  • write-gated (binding) NS records are approved only in specific cases and are refused to an account without an is-a.dev subdomain held for at least 30 days; review takes usually 24 to 72 hours and up to 2 weeks source
  • write-gated (binding) a root subdomain must belong to a software-development-related project; the eligibility is part of the review source
Bindingwrite-gated the operator reviews each request and states it can terminate a subdomain at any time for any reason, so the owner can withdraw the name; the zone is the operator's and the registrant holds records only, apart from approved NS cases
Identityemail a GitHub account of an individual; the only owner field the JSON file requires is the GitHub username, and a GitHub organisation account cannot register; no phone and no card are asked (https://docs.is-a.dev/domain-structure/)
Egressno query cap published
Per-object capno subdomain count per account is published on the pages read; only one single-letter subdomain per user is allowed
Retentionno expiry or renewal term is published; a subdomain lasts until the maintainers remove it or its JSON file is deleted by a pull request
Interfacegit every create, change or delete is a pull request against the register repository with a JSON file per name; the supported record types are A, AAAA, CAA, CNAME, DS, MX, SRV, TLSA, TXT and a service-specific URL redirector, and NS only in approved cases
Toolinggit and a GitHub account; a pull request for each change, merged by a maintainer
Composes witha CNAME to a free static host gives a named site; the zone is not yours (NS delegation is refused to an account that has held a subdomain for under 30 days and is otherwise decided case by case), so it cannot become a Cloudflare zone of its own by default
Reliabilitythe operator can remove a subdomain at any time for any reason, the service is run by volunteers and the TLS limit is per name because the suffix is on the Public Suffix List
NotesWithdrawal binds first: a maintainer's pull-request review stands between the request and the name, and the operator can end the name at any time. The zone is not the registrant's, so there is no own zone, no Cloudflare zone and no wildcard certificate for the subdomain by default. The TLS limit does not bind, because the suffix is listed and each name counts alone against the Let's Encrypt limit.
