Limits
  • request-rate none observed: 10 consecutive searches in one session, all 200
  • request-rate 500 results per request maximum; a limit above 500 silently returns the 50-result default
The clamp is the only ceiling that behaved like a quota. Measured: limit=500 returned 178 items (all matches for 'linux'), limit=200 returned 178, limit=100 returned 100, limit=501 returned 50, limit=999 returned 50, limit=1000 returned 50. The three clamped responses are byte-identical to the default one (sha256 964a100b...), so the server is not truncating a larger answer: it is ignoring the parameter and serving the default page. A client that asks for 1000 gets fewer results than one that asks for 200, with HTTP 200 and no error element.
Bindingnone There is no daily counter and no byte quota, so nothing in the vocabulary fails at a 1 TiB/month habit. The first thing a client actually meets is the results-per-request clamp above 500, which the vocabulary has no kind for.
Identityanonymous Nothing: no account route (caps says registration unavailable), no key, no cookie needed for caps, search or get.
EgressNo metering and no account. The API returns RSS with NZB enclosures; each NZB measured 7,346 bytes.
Per-object capnot applicable per object, but the request accepts at most 500 results: <limits max="500" default="50"/> in caps
Retentionnot stated in caps or on the page. The index is Spotnet-derived, so its depth follows the Spotnet post history rather than a vendor commitment.
Interfacerest A Newznab-shaped API on /api. caps advertises <server type="Spotweb" version="0.1"> with search, tv-search and an NZB endpoint at /api?t=g&id=<message-id>. No apikey parameter was required for caps, search or get.
endpoint: https://www.nzbserver.com/api?t=caps ; https://www.nzbserver.com/api?t=search&q=<query> ; https://www.nzbserver.com/api?t=g&id=<message-id>
ToolingAny Newznab client can use it: Prowlarr and NZBHydra2 both accept a generic Newznab indexer with a URL and a key, and this endpoint ignores the key. Sonarr, Radarr, Lidarr and Mylar therefore work without a wrapper. There is also a Spotweb web UI at /?page=index with per-post NZB links.
Composes withThe only indexer among debrid providers that needs neither an account nor a key, so it is the zero-identity default for an arr stack; its Dutch Spotnet catalogue is the gap that a second indexer fills.
ReliabilityA stock Spotweb install (caps still carries the default placeholder email 'john@example.com (Jane Doe)') run by a volunteer; a third-party listing records 'inconsistent uptime, 4.6s response time when operational', so a client should not make it the only indexer.
NotesThe 7,346-byte NZB has the same sha256 as the one spotnzb.com served for the same message-id, so the two instances share a Spotnet backend or mirror the same database; the search feeds differ slightly in size (41,868 vs 41,244 bytes) but start with the same item. Treat them as one catalogue reachable at two hostnames, not as two independent indexers.
Evidence notemeasured caps, search and NZB download were all run today with status, bytes and digest. The retention and uptime figures are third-party and are labelled as such.
