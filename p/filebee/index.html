The 'Anti Limit V5' badge is the vendor's claim that the wrapper defeats Drive's download limit. The sibling service DriveSeed lists '403: User Rate Limit Exceeded - Fixed to Great Extent' among its fixes, which is the same limit seen from the other side of the chain and confirms the limit is real and recurring.
Bindingper-ip-shaping At 1 TiB a month the wall is Google's per-file and per-session throttling, not a FilePress quota: FilePress publishes none. The wrapper exists to move that throttle, so the constraint travels with it rather than disappearing.
Identityemail Publishing needs an account (the homepage offers 'Open Login'); the signup form was not read, so whether the gate is an email address or Google OAuth is unverified. Downloading needs nothing: 'Users can download File Directly Without Login'.
EgressThe download is served as a 'Direct Download' without login. The page claims 'Anti Limit V5 - File will never get any Limit', which is the product's whole reason to exist: it interposes itself between the downloader and Google Drive's per-file limit.
Per-object capNo per-file size is stated for the wrapper itself. The two stated ceilings are feature limits: Telegram upload 'Support Upto 15GB' and watch-online 'Support Upto 20GB'.
RetentionNot stated. A link points at a Google Drive file id, so it lives as long as that Drive file does.
Interfacerest, unknown REST: POST {Domain}/api/v1/file/add with a JSON body carrying a key, a Google Drive file id, quality, genre, tmdb_id, season and episode numbers, and an isAutoUploadToStream flag. Documentation is published at api.filebee.xyz, which titles itself 'FilePress API' and 'Documentation for the Kittn API'. Also 'Auto Upload To MirrorAce & MirroredTo - Just Add there api keys in your profile section'.
endpoint: https://api.filebee.xyz/api/v1/file/add
ToolingNo client exists and none is needed: a POST with a JSON body and a key copied from the account does the publish. The published example carries a live-looking key value in the documentation itself; that is the vendor's sample, not a credential of ours.
Composes withThe publish step of the Indian index chain: an index site posts a FilePress link, FilePress wraps a Google Drive id into a page, and the downloader lands on a Drive file whose per-file limit the wrapper exists to dodge. It feeds HubCloud, DriveSeed and GDFlix, which all wrap the same Drive id again one layer down.
ReliabilityThe brand has moved domains repeatedly: filebee.xyz, filepress.cloud and filepress.wiki all resolve to the live app at new2.filepress.lat, filepress.xyz is parked for sale at USD 1,299, and filepress.info plus filepress.buzz could not be checked at all because network requests refused both (HTTP 530 at network requests, exit 4), so their state is unknown rather than dead. Any hard-coded hostname in a user breaks.
NotesIt is not storage: it is the publish step of the chain that turns a Google Drive file into a share page. The record exists so the subsequent audit prices the chain correctly and does not re-open filepress.info, which is dead.
Evidence notedocumented The feature list, the API endpoint and the 15/20 GB ceilings were read on the vendor's own pages. What the record does not have is a measured download, so the 'Anti Limit' claim and the true throttle remain unverified.
