Per-object-cap 256 GB. Retention: 'Uploaded files are kept for at least 365 days. Files that have not been downloaded for more than 365 days will be automatically deleted'. A sliding window, not a hard expiry, so a monthly GET sweep keeps everything alive indefinitely. No auth, no rate limit observed: 4 concurrent ranged GETs all returned 200 in 1.7-3.3 s.
Identityanonymous No registration is required and the vendor states that no email, phone or personal information is needed; uploads are handled anonymously.
EgressUnmetered. 'No speed limits. Speeds depend solely on your network bandwidth. We don't impose any artificial throttling.' Downloads served from Cloudflare with Cache-Control: public, max-age=3600.

Interfacerest, rclone rest
ToolingUndocumented but functional chunked HTTP API, reverse-engineered from the site's own uploader JS: POST https://u1.bigfile.net/v1/upload with header Content-Range: start-end, header Hash: <sha256 of whole file encoded base62>, raw body = the chunk; response {"status":true,"uri":"/d/<base62hash>"}. Read path: GET https://www.bigfile.net/d/<base62hash> (direct octet-stream), plus GET /d/<hash>/list.json for multi-file shares. Uploader parallelises across u1..uN.bigfile.net. No rclone backend.
Composes withAllows unlimited uploads per IP address with up to 256 GB per object. Objects have 365-day sliding retention based on access activity. Content addressing allows re-uploading identical hashes to refresh retention.
ReliabilityUpload and read verified by SHA-256 on 2026-11-01. Site advertises a zero-database architecture without persistent file inventories. Lost hashes cannot be enumerated or recovered due to the lack of user accounts.
