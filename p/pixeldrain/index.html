Free uploads require an API key (anonymous server-side PUT returned 401 authentication_required). 6 GB/day/IP download cap; 1 MiB/s throttle and 3 concurrent downloads after that. Files expire 60 days after last download; a download only counts if >10% of the file was transferred in one request, and the timer only updates once per 24h. Hotlinking not supported on free.
Bindingretention-clamped a clock, not a quota: bytes leave whether or not transfer is completed
Identityinstitution (inferred, not read) not published
EgressFree egress capped at 6 GB/day per IP address (sliding 24h window, IP-bound even when logged in); over the cap the speed drops to 1 MiB/s and max 3 concurrent downloads. Pro: 4 TB per 30 days. Prepaid: EUR 1/TB metered. So free egress is metered, not unusable. 6 GB/day x N IPs.
price per tb: EUR 1/TB
RetentionFiles expire 60 days after last download; a download only counts if >10% of the file was transferred in one request, and the timer only updates once per 24h (60 days)
Interfacerest, rclone rest
ToolingFull REST API at /api with HTTP Basic (api key as password). rclone has no official backend; the API is simple enough that wrappers abound (Atlas electron/downloads/hosts/pixeldrain.js). PUT https://pixeldrain.com/api/file/ with -u :APIKEY.
Composes withAPI keys are free and per-account, but the real multiplier is IP: the 6 GB/day download cap is per IP, so egress scales with egress IPs (proxies/CF Workers) not accounts. Storage itself is 'No limit' on free, which is the interesting half.
ReliabilityOperator states plainly that free-plan 'unlimited' is not for storage: 'If you are (ab)using pixeldrain for free storage, you should not be surprised when the rules change at some point and all your stuff suddenly disappears.' The 6 GB/day free cap and 10%-of-file rule make this a poor serving tier unless fronted by something that fans out across IPs.
