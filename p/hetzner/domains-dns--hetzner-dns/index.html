Egressno DNS query cap published on the pages read
Per-object capup to 500 records per zone and 50 records per RRset, the 500 raisable on a justified demand; up to 25 zones by default
Retentiona zone that is not delegated to the Hetzner name servers for more than 28 days is deleted automatically; nothing else is stated about inactivity (28 days)
Interfacerest, cli the Hetzner Cloud API at https://api.hetzner.cloud/v1/ with an Authorization Bearer project token: POST /zones creates a zone, and POST /zones/{id_or_name}/rrsets/{rr_name}/{rr_type}/actions/set_records replaces the records of a record set; there is no dyndns2 or HTTP-GET update URL, so a dynamic update is an API call with a token; the default rate limit is 3600 requests per hour per project; zone names must be a registrable domain under a public suffix, not a subdomain
Toolingcurl, the hcloud CLI (hcloud zone create), BIND zone-file import, and AXFR secondary zones against an external primary
Composes witha zone can also run as a secondary that copies a primary elsewhere by AXFR, and a zone can be shared across projects for managed certificates and load balancers; it cannot hold a name that is not a domain you own
Reliabilityan undelegated zone is deleted after 28 days, and a new account can be asked for an ID copy or a card prepayment before it can order
NotesConfirmation interval: none for a delegated zone; the only inactivity rule found is the 28-day deletion of a zone that is not delegated to Hetzner name servers. It is authoritative DNS for a domain the user already owns, not a free subdomain or a dynamic DNS hostname service.
