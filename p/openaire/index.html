Bindingrequest-rate At 8.38 MB per call and 4.2 s per call, one connection moves about 2 MB/s; with no published cap the unknown is how many calls the service tolerates before a 429, which is what decides the day.
Identityanonymous No key, no account: both calls answered 200 anonymously. Nothing on the docs page asks for registration.
EgressFree and unmetered for the public API endpoints.
free allowance: no byte allowance published
Per-object capnot applicable: XML or JSON per query. size=100 returned 8,384,696 bytes in one response here, so a page is megabytes rather than kilobytes.
Retentionthe graph is rebuilt from source repositories and deduplicated; records reflect the last harvest, not a fixed snapshot
Interfacerest, cli GET https://api.openaire.eu/search/publications?title=...&size=N (XML by default, format=json available); the newer Graph API sits under https://api.openaire.eu/graph/.
endpoint: https://api.openaire.eu/search/publications
Toolingcurl/python-requests; the openaire python client exists but the endpoints are plain HTTP.
Composes withThe widest single metadata source among debrid providers per call: 8.4 MB per size=100 page means a few thousand calls moves tens of GB of linked records, which is a different order from Crossref's 0.77 MB pages.
ReliabilityResponses are large XML by default, so a client that forgets format=json spends bandwidth on tags; the search endpoint and the newer graph endpoint are different APIs with different shapes.
NotesThe highest bytes-per-call of any metadata API among debrid providers by an order of magnitude, which makes it the best candidate for filling a day with metadata when the file hosts are the bottleneck.
