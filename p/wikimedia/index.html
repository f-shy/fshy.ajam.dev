Limits
  • per-ip-shaping (binding) capped at 3 connections per IP, and rate limited; measured here at 1.661-2.617 MiB/s over one connection (three runs) and 2.647-7.649 MiB/s total over eight connections (three runs), so parallelism helped up to 3.6x and the cap did not refuse the eighth connection source
The User-Agent policy is enforced: a client without a descriptive agent may be blocked, and evasion attempts are named as a blocking reason on the front page.
Bindingper-ip-shaping The documented 3-connection cap is a connection count, not a byte rate: eight parallel range reads all returned 206 and the best of them reached 7.649 MiB/s, which is about 645 GiB/day.
Identityanonymous No account and no key; a descriptive User-Agent is the only requirement, and it is not a credential.
EgressFree, but conditioned on the User-Agent policy: 'If you are reading this on Wikimedia servers, please note that we are now enforcing the Wikimedia Foundation User-Agent Policy for dumps downloads. Downloads are also rate limited and capped at 3 connections per-IP ... Clients that do not respect the user-agent policy or who try to evade these limits may be blocked.'
free allowance: no byte allowance published
Per-object capnot applicable: one compressed file per dump. enwiki-latest-pages-articles.xml.bz2 is 25,800,511,704 bytes; ranged reads are supported (accept-ranges: bytes).
Retentionmonthly snapshots are kept; 'latest' is replaced each run and older dated directories persist for a period the dump index does not quantify
Interfacerest, rsync, cli HTTPS per file with Range support; rsync mirrors are listed on meta.wikimedia.org; the dump index at /backup-index.html gives every file with size and checksum.
endpoint: https://dumps.wikimedia.org/enwiki/latest/
Toolingcurl/wget with a descriptive User-Agent, rsync against a mirror, and the checksum files that ship beside each dump.
Composes withA fixed encyclopaedia corpus to join against Common Crawl's web text; the 24 GiB article dump is small enough to hold beside a dataset snapshot, and the mirror list is the escape hatch when the per-IP cap binds.
ReliabilityThe dump format is changing: XML dumps sunset in January 2027, so a pipeline built on pages-articles.xml has a dated migration to the Content File Exports format.
NotesCaveat is the 2027 format change and the 3-connection rule. A single connection gives about 178 GiB/day at the mean, and the best eight-connection run reached 645 GiB/day - which the published cap says a client should not do. The whole English Wikipedia article dump is one day's single-connection allowance.
Evidence notemeasured The file size came from a HEAD and the rate from a 64 MiB ranged read, three runs at each concurrency. All eight parallel requests returned 206, so the documented 3-connection cap did not refuse them at the transport level - whether it is enforced by rate, by UA or only at peak is not established.

Limits
  • per-object-cap (binding) 5 GiB/file source
  • write-gated review at the community level source
5 GiB/file, 100 MiB without chunking; per-licence/scope review at the community level; thumbnailing capped at a 59 s timeout, 100 MP for GIFs
Identityemail Email. Account is username+password+email, no affiliation. Note the nuance: upload itself is in the base user group, but reupload (overwrite) needs autoconfirmed. So first uploads are open; overwriting an existing file needs account age.
Egressfree, unmetered, CDN (upload.wikimedia.org), no auth, Range supported. Wikimedia runs its own edge cache in front of Swift.
Per-object cap5 GiB/file (5368709120 bytes)
Interfacerest, cli MediaWiki Action API + REST; action=upload with stash/filekey for chunked; upload_by_url right for server-side upload
Toolingmwclient / pywikibot / commons-cli; upload and upload_by_url are granted to the plain user group (verified in siteinfo usergroups), so a brand-new account can already do server-side upload without waiting
Composes withupload_by_url means Commons fetches the file from YOUR url. No local bandwidth at all. Files land at upload.wikimedia.org/wikipedia/commons/<x>/<xy>/<name>, hash-addressed and immutably versioned.
ReliabilityThe one platform here where a multi-TB batch is explicitly contemplated. Commons asks you to warn sysadmins before 'batch uploads amounting to several TB', which is an acknowledgement that people do it.
