Free tierThe gotify/server binary and the gotify/server Docker image are published at no cost under the MIT license: the user installs and runs the server on a machine the user supplies, with a REST API for sending messages and a WebSocket stream for receiving them. The project publishes no hosted SaaS subscription and no usage quota.
unit none; metered on none; The unit counted is not a quota: the software is free and the user supplies the machine. Hosted Gotify is sold by third parties who install and run the same software on a rented machine, and those hosted lanes are named before this option.

Limits
  • write-gated (binding) an application token is required to push a message, and from Gotify 3 that token is shown only once, on creation or rotation source
No request rate, message count, retention window or object size is published by the project; the machine the user runs sets the practical ceiling.
Bindingwrite-gated Pushing a message needs an application token that is shown only once at creation or rotation, so losing it stops writes until a new token is made.
Identityanonymous No registration with the project is needed: the user installs the server and sets its administrator password locally, and the owner creates application and client tokens inside the server. The Docker Compose example sets the initial administrator password with GOTIFY_DEFAULTUSER_PASS, and the owner changes it after first sign-in.
Egressnot metered by the project: the server runs on a machine the user supplies, so outbound traffic follows that host's network terms; messages reach clients over a WebSocket stream opened by the server
Per-object capunverified: no per-message size cap is stated on the first-party pages read
RetentionMessages remain in the server's own database file, which the install guide tells the user to include in backups; the API exposes endpoints to delete all messages, all messages of an application, or a single message. No automatic expiry is stated on the pages read.
Interfacerest, cli A REST API at the server's own URL takes messages with an application token in an X-Gotify-Key header, a token query parameter or an Authorization bearer header; basic auth is for creating a client token only. Messages stream to clients over WebSocket at /stream. The gotify/cli tool and any HTTP client can push. No hosted endpoint is published by the project.
endpoint: unverified: the endpoint is the machine the user runs; no first-party hosted endpoint is published
ToolingThe user installs and runs the server: a platform zip from the gotify/server GitHub releases, or the multi-arch Docker image gotify/server with a mounted data directory for the SQLite database and images, configured through a gotify-server.env file. Application and client tokens are created inside the server. The gotify/cli tool or any HTTP client pushes messages; the Android app or the built-in web UI receives them over the WebSocket stream.
Composes withThis offer is software the user installs and runs on a machine of the user's choosing; the user also supplies the database backup, TLS termination and upkeep. Hosted push services are considered before this option.
ReliabilityThe project states no quota, throttle or automatic message expiry on the pages read. The application token is shown only once from Gotify 3, so it must be stored when issued. History lives in the server's data directory and is lost if that directory is not kept across a container replacement.
NotesGotify is software the reader installs and runs. No official hosted SaaS tier was found on the first-party site or the repository: the project's pricing and cloud paths answered 404. Third parties sell managed Gotify on rented machines; those are hosted lanes of the same software and are named before this option.
Evidence notedocumented The software, install path, API authentication and token handling are read on the first-party site, the project repository, the install guide, the push guide and the API reference. The server was not installed or run, so no operating figure is measured.
