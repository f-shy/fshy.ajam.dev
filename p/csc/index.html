Free tier10 TiB per CSC project by default. The quota table lists 'Allas / Storage / 10 TiB' with the increase path 'Contact CSC Service Desk'. There is no per-file or per-object size cap documented; the counted limits are 1,000 buckets per project and 500,000 objects per bucket. Above 200 TiB for free-of-charge users, CSC asks you to 'agree with CSC about storage terms and possible costs'.
unit objects; metered on stored-bytes

Bindingnone 10 TiB per project is real and the door has a gatekeeper: CSC accounts come through Haka/Virtu or a Finnish organisation's contract. Identity binds before any limit does.
Identityinstitution (inferred, not read) not published
EgressUnmetered. Objects are served from the a3s.fi S3 endpoint; public buckets are readable by anyone over HTTPS with no key and no egress meter. Quoted rule: 'Making a bucket public means that every file and directory on the bucket will be accessible without any kind of authentication from anywhere on the internet using the HTTPS protocol.'
Interfaces3, rclone, cli s3
Toolingrclone (s3 backend, endpoint a3s.fi), s3cmd, aws cli, Swift/OpenStack CLI, a-commands suite (github.com/CSCfi/allas-cli-utils), Allas web UI at allas.csc.fi. The a-publish helper makes a bucket world-readable and prints the public URL.
Composes withOne project = 10 TiB. Self-service is the multiplier: a CSC account holder in the Haka/Virtu federation can create additional Academic projects in MyCSC without a human gate ('Academic project category ... can be created only by members of Finnish higher education institutions, state research institutes and CSC', and project creation is a MyCSC button, not a review). Each new project brings its own 10 TiB Allas bucket quota, its own 1,000 buckets and its own 500k-object/bucket ceiling. Ten projects = 100 TiB with no conversation with anyone.
ReliabilityStorage-BU exhaustion closes the project; project lapse is what deletes data, not a retention timer.
