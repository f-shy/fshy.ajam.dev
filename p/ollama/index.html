RetentionClient-side chunking is 100 MB-1 GB parts (server/upload.go). Retention: none. Objects persist until deleted; no TTL anywhere in the docs.
Interfaceoci oci
ToolingNative OCI Distribution v2. ollama push / ollama pull, oras/skopeo/crane all work. Push requires a free ollama.com account (WorkOS authkit signup, no payment); pull is fully anonymous. ollama create accepts safetensors dirs, GGUF, split GGUF globs, and any layer content. A pushed model is just OCI layers, so arbitrary bytes ride as application/vnd.ollama.image.model.
Composes withunlimited free namespaces x unlimited repos x unlimited tags; the binding per-object ceiling is whatever the server accepts, and 455 GiB single-blob objects already exist in production. 30 TiB = 66 objects the size of huihui_ai/kimi-k2-abliterated. Multiply by free-account count. This is structurally identical to GHCR but with a ~45x larger observed per-object ceiling and no documented 10 GB layer cap.
ReliabilityPushes to large blobs are flaky: issue #6466 reports 502 Bad Gateway at 40-50% of an 8.5 GB upload, and #13740 reports 413 on 100 GB. Resume/retry is required, and ollama push is not resumable by default. Reads were 100% stable in every probe.
