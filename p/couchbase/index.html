Free tierOne free tier operational cluster per organization: 1 node, 8 GB RAM, 8 to 10 GB data storage depending on cloud, SQL++ and key value, Search (vector, FTS, geo), Mobile App Services, RBAC with scopes and collections, forum support; no credit card required and free for continuous use while active
unit GB; metered on stored-bytes; The pricing page states 1 node and 8 GB of RAM. Cloud reference pages give the data-storage allowance as 10 GB on AWS and Azure and 8 GB on GCP. The plan is perpetual while the cluster is active, not a trial.

Limits
  • volume-quota 1 free tier operational cluster per organization; 10 GB data storage on AWS and Azure and 8 GB on GCP; 1 node, 8 GB RAM source
  • retention-clamped (binding) cluster turns off after more than 72 hours of inactivity with data preserved, and is deleted after more than 30 days of inactivity source
  • request-rate Data API is limited to 10,000 requests per second per node; payloads restricted to 100 MB source
Bindingretention-clamped The cluster is deleted after 30 days without activity, so a workload with a persistent idle gap fails before the 8 to 10 GB storage or the 10,000 requests per second interface limit is reached.
Identityemail The sign-up page offers Email Address, GitHub Account or Google Account. The billing docs state no credit balance or credit card is needed for the Free plan.
EgressCapella passes through cloud-provider data transfer charges based on GiB and transfer type. Internet egress is commonly .09 credits per GB in North American and European regions; inter-zone or intra-region transfer is commonly .01 credit per GB on AWS and GCP and free on Azure. Data import into Capella and transfer between instances in the same Availability Zone are free. No free egress allowance is published for the free plan.
Per-object capunverified: the free-tier page does not state a per-document size cap; the Capella Data API platform limit is 100 MB per request and response payload, but that is an interface limit and not a stated per-object cap on the free tier
RetentionData and state are preserved while the cluster is active. After more than 72 hours without activity Couchbase turns off the free cluster and linked App Services, preserving data and state; after more than 30 days without activity Couchbase deletes the cluster and linked App Services. Upgrading from the free plan to a paid Support plan also deletes the existing free cluster. (30 days)
Interfacerest, cli Couchbase SDKs (Java, Python, Node.js, PHP and others) connect over the couchbases:// TLS protocol; a RESTful Data API exposes document CRUD under /v1/ with passthrough to Query and Search services; a Management API and the Capella web console manage the cluster.
endpoint: couchbases://<cluster>.dp.cloud.couchbase.com
ToolingCouchbase SDKs (Java, Python, Node.js, PHP), any HTTP client such as curl or Postman against the Data API, the cbbackupmgr CLI for backup, the Capella web console, and a Management API key for automation
Composes withA free Capella cluster can hold a document and vector store behind a free Worker or tunnel for a public REST path, with the SDK or Data API as the write interface.
ReliabilityThe free cluster turns off after 72 hours idle and is deleted after 30 days idle; upgrading to a paid plan deletes the existing free cluster, and the backup and restore, private endpoint, network peering, audit log and on/off schedule features are not available on the free tier.
NotesThe free tier is a real managed Couchbase Server cluster, not a sandbox. Two caveats bind: the cluster is deleted after 30 days idle and upgrading to a paid plan deletes it, so data must be backed out with cbbackupmgr before either. The storage allowance differs by cloud: 10 GB on AWS and Azure, 8 GB on GCP. The per-document cap is not published; the 100 MB figure is the Data API payload limit, not a free-tier object cap. Couchbase Server is also available as self-hosted software, but that offer is the last resort and is not the offer recorded here.
