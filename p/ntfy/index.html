unit requests; metered on request-count; The headline free unit is the daily message count, denominated in requests (messages). The tiers endpoint also states messages_expiry_duration 43200 seconds (12 hours), attachment_file_size 2097152 bytes (2 MB), attachment_total_size 20971520 bytes (20 MB), attachment_expiry_duration 10800 seconds (3 hours), emails 5 and calls 0. The unit-free to sign-up is anonymous; billing accounts and card details apply only to paid plans, which are out of scope for this hosted free-tier record.

Bindingvolume-quota The 250-message-per-day ceiling keyed to IP address is the first threshold a script reaches at normal alerting volume, before the 60-request burst rate or the 200 MB bandwidth budget.
Identityanonymous No account is needed for the hosted free tier: the terms state 'You may use the Service without creating an account or subscribing to a paid plan.' The home page says 'Try ntfy for free without sign-up' and the publish docs say 'Because there is no sign-up, the topic is essentially a password'. No email, phone, card, ID or institution is asked for to publish or subscribe on the free tier. A valid payment method via Stripe is required only for a paid Subscription, which is out of scope for this free-tier record.
EgressTraffic out is metered only as a daily bandwidth budget: by default 500 MB per visitor in 24 hours covering attachment transfers and cache replay, and on ntfy.sh the daily bandwidth limit is 200 MB. Exceeding it returns HTTP 429 with ntfy error code 42905 and no messages are written. No per-GB price is stated for the free tier.
free allowance: 200 MB per visitor per 24 hours on ntfy.sh free
Per-object capEach message can be up to 4,096 bytes long; longer messages are treated as attachments. On the free tier an attachment is at most 2 MB (2097152 bytes) per file and 20 MB (20971520 bytes) total per visitor. (2097152 bytes)
RetentionMessages are cached server-side for 12 hours by default (43200 seconds on the free tier); attachments expire after 3 hours (10800 seconds on the free tier).
Interfacerest, cli Publishing is an HTTP PUT or POST to ntfy.sh/<topic> with the message as the body and headers for title, priority, tags and attachments. Subscribing uses a GET streaming API at <topic>/json, <topic>/sse or <topic>/raw, or WebSockets at <topic>/ws, all documented. The ntfy CLI publishes and subscribes from a shell. A free anonymous user publishes to any unreserved topic name with no authentication, so the topic name acts as the credential.
endpoint: https://ntfy.sh
Toolingcurl or any HTTP client for PUT/POST publishing; the ntfy CLI; official client libraries for JavaScript, Go, Python, PHP and PowerShell shown in the docs; official Android, iOS and web apps for receiving. Client SDKs exist for common languages.
Composes withA worker or script on any free compute service sends one HTTP PUT/POST to ntfy.sh to reach subscribed phones and desktops; healthchecks.io, GitHub Actions, Ansible, Home Assistant and Uptime Kuma are named integrations.
ReliabilityBest effort only: the FAQ states the service runs on a single DigitalOcean droplet without scale out or redundancy; short blips and HTTP 500 spikes have occurred. Traffic over the daily bandwidth budget returns HTTP 429 (error code 42905). Repeatedly exceeding limits may temporarily ban the IP address.
Notesntfy has both a hosted free server (ntfy.sh) and self-hostable open-source software; this record documents the hosted free offer, not the self-hosted software, so self_hosted is absent. The cheapest paid tiers (Supporter USD 6 monthly or USD 5 yearly, Pro USD 12 or USD 10, Business USD 25 or USD 20) are out of scope for this free-tier record. The free tier is anonymous and keyed to IP address, so a shared IP can inherit another user's rate limit. No live publish probe was run. Revisit when the tiers endpoint changes the free message count or the attachment cap.
