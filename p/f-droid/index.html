Free tierNo published total or per-app byte quota. The archive is large and browsable: index-v2.json is 66,480,070 bytes and a single APK (org.fdroid.fdroid) is 12,426,276 bytes. Builds are produced by F-Droid's own build farm from source in fdroiddata; the 24-48 h publish latency is due to human keystore signing.

EgressFree. Mirrored via f-droid.org and third-party mirrors. No billing.
Retentionper-object-cap: none documented for the published APK; the build environment is documented in GB terms (1000 MB container, 800 MB build, 4000 MB for the large path) which caps what can be built. retention: indefinite - F-Droid keeps all published versions
Interfacerest, rclone, cli rest
Toolingfdroid CLI (fdroidserver), the repo is a plain signed index (index-v2.json / index-v2.jar) with APKs at /repo/<pkg>_<vc>.apk. Clients: fdroid, vanilla Android F-Droid client. No rclone backend.
Composes withunlimited apps x unlimited versions (every published version stays in /repo, keyed by versionCode). Multiply by unlimited GitLab/Codeberg source repos and unlimited forks. But each app is reviewed and built by F-Droid's farm - so this is a per-app, human-gated store, not an arbitrary-blob host.
ReliabilityFully programmatic on the read side (static index + APKs, range-capable in principle), but the write side is a merge request into fdroiddata built on F-Droid's farm with human keystore signing - 24-48 h latency. Cannot store arbitrary blobs; must be an Android app build.
