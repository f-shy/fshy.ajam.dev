RetentionNot stated. The output is a link to a file held on the operator's seedbox; how long it survives is unpublished.
Interfaceunknown A Telegram bot only. There is no HTTP endpoint: the interface is a chat with @MagnetLinkDLBot, and the operator publishes a fallback bot (@MagnetLinkDL2Bot) rather than an API.
ToolingTelegram client. Automating it means a Telegram user session against a third-party bot, which is the opposite of the programmatic access these records prefers.
Composes withThe cheapest known conversion from a torrent to an HTTP link with no client, no disk and no seeding: a magnet goes in, a link comes out, and the download happens elsewhere. It is the debrid function reduced to one chat, with no published capacity behind it.
ReliabilityThe operator runs a spare bot for when the main one breaks, which is an honest statement about uptime. A third-party bot sees every magnet a user submits, and the resulting link is served from infrastructure nobody in these records controls.
NotesDocumented as a service because it resolves and fetches: a magnet is supplied and a link to bytes comes back. The ledger's account-mirror bots (for example anything that clones into a user's own Drive) are excluded by that same test and listed in findings.md instead.
Evidence notereported The service's existence and function come from its own Telegram profile, which is its operator's claim. No magnet was submitted, so neither the conversion nor any speed is measured. Moving up needs one torrent run end to end.
