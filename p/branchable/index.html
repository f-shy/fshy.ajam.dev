Per-backend: file size caps, per-day upload quotas, API rate limits all apply unchanged. rclone's Drive backend has its own 750 GB/day upload cap; OneDrive throttles. Encrypted annex remotes lose rclone's server-side dedupe.

Free tierN/A by itself. Inherits whatever S3-compatible store you point it at. This is the multiplier: any free S3 endpoint (Internet Archive s3.us.archive.org, HF s3.hf.co, Oracle/Cloudflare-adjacent object tiers, MinIO on a free VM) becomes a versioned large-file store with git-annex's own manifest.
unit mixed; metered on stored-bytes
Pricenone stated
Identityemail (placeholder) not published
EgressDetermined by the backing S3 store. Parameter publicurl enables downloads via direct HTTP GET, and parameter signature=anonymous allows unauthenticated read-only access.
Interfaces3, git part of the text of Free tier, above
Toolinggit-annex (Haskell, standalone Linux/macOS builds, ~1.5k stars on the mirror). Config via git annex initremote type=S3 host=... bucket=... requeststyle=path. Internet Archive has a documented special mode (host=s3.us.archive.org) where git-annex writes x-archive-meta-* headers and records the public URL, so every annexed file is also fetchable from archive.org with no login.
Composes withOne special remote per bucket; fileprefix= lets many remotes share one bucket. The allowance is per account, so each free S3 account adds one bucket. Because git-annex keys content by hash, the S3 side is a dumb blob store. A client can shard the same dataset across several free stores, and git-annex tracks which copy is where (git annex whereis). Chunking (chunk=1MiB) avoids per-object size caps on the backing store.
ReliabilityMature and boring — the special remote has existed for over a decade. Failure mode is backend-side (IA's S3 endpoint was unreachable: connect timeout on s3.us.archive.org:443, and archive.org/help/abouts3.txt returned 522 through the proxy), not annex-side.

Free tierN/A. A protocol adapter. Turns ANY git-lfs server (GitHub, GitLab, Bitbucket, a self-hosted Gitea) into an annex special remote, so the LFS host's quota applies but annex adds hash-verified partial clone and whereis across mirrors.
unit mixed; metered on unstated

Identityemail (placeholder) not published
EgressDetermined by the underlying Git LFS host.
Retention| Cannot delete = every mistake is permanent on the LFS side, and the host's month-storage accounting (GitHub) means you keep paying for it in quota
Interfacegit part of the text of Free tier, above
Toolinggit annex initremote lfstest type=git-lfs url=... encryption=shared. Supports gcrypt:: URL prefix for encrypting the git side too.
Composes withBecause annex can hold the same content on several LFS remotes, you can stack the 10 GiB/project GitLab allowance and the 10 GiB GitHub allowance as tiers of one logical dataset, with annex tracking which objects live where. Sharding a 1 TiB corpus across 100 GitLab projects becomes a git annex copy --to loop.
ReliabilityCannot delete = every mistake is permanent on the LFS side, and the host's month-storage accounting (GitHub) means you keep paying for it in quota. No batching + per-object request = the exact workload LFS rate limits are designed to stop.
