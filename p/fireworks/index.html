  • request-rate serverless limits per model are tokens per minute, not requests: three adaptive meters (total prompt, uncached prompt and generated TPM) start at an unpublished default and rise 25% at most once every 15 minutes toward a ceiling set by model size and spend tier. The published ceilings (for a model under 800B parameters: 216M total prompt, 54M uncached prompt and 2.16M generated TPM) apply at Tier 3 and above; an account with no payment method is below Tier 1 (which needs a valid payment method), and no page publishes its starting default or its ceiling (unverified: not published). source
  • request-rate concurrency, not a rate: the Serverless Training API allows 8 active runs per account by default (account overrides may differ); some pool models also cap active runs per account on that base model, with managed fine-tuning jobs on it counting toward the cap, and a run over either cap fails with RESOURCE_EXHAUSTED. source
