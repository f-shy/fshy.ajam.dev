Free tierFree base plan: 10 GiB included disk, 1-hour runtime limit on the pricing page (24 hours in the billing docs), 20 concurrent sandboxes, CPU and memory from the template; runtime and retained storage billed separately. No free runtime: sandbox creation requires a balance above zero and card top-ups start at €5.
unit hours; metered on wall-clock; The free item is the Basic team base price, not free runtime; a positive balance is required before a sandbox is created, restored or resumed. Runtime is EUR 0.000020 per vCPU-second plus EUR 0.000004 per GiB-second, about EUR 0.1584 an hour for 2 vCPU and 1 GiB as the billing page computes it. The pricing page says a 1 hour runtime limit; the billing page says 24 hour max runtime for Basic.

The Basic plan's runtime limit is stated as 1 hour on the pricing page and 24 hours in the billing docs; the discrepancy is unresolved. Retained disk is EUR 0.10 per GiB-month and checkpoints and templates are EUR 0.03 per GiB-month.
Bindingvolume-quota The positive-balance start check binds first: a team with no credited balance cannot create a sandbox at all, before runtime or storage meters apply.
Identityemail The signup form at dash.watasu.io/users/sign_up asks for 'Your name', 'Work email', 'Password' and 'Confirm password'; no phone or identity-document field is shown. A saved card is not required, but a positive balance from a card top-up (minimum EUR 5) is required to start a sandbox. Card and usage details beyond the signup form are unverified: behind a sign-up.
EgressNo bandwidth or egress charge: 'No. Bandwidth is included with your plan, sized to match — normal app traffic at any tier isn't metered, shaped, or invoiced per GB.' Sandbox networking supports an HTTPS preview URL and configurable internet access; no per-sandbox byte allowance is stated.
Per-object capnot applicable: the unit is a machine, not an object. Basic teams get a 10 GiB plan-managed root disk.
RetentionInactive sandbox disks expire after seven days, including paused, stopped, failed and lost sandboxes; named persistent volumes and reusable template versions are not subject to this expiry. (7 days)
Interfacessh, rest, cli One SSH command opens a shell in a fresh sandbox using a template name and the box.watasu.io host; the HTTP API lives under https://api.watasu.io/v1 with an API-key bearer token, and the CLI offers watasu ssh.
endpoint: https://api.watasu.io/v1
Toolingan SSH client, the watasu CLI and the official Python, JavaScript and Rust SDKs; no rclone backend is documented.
Composes withA paused sandbox keeps its disk and machine state for up to seven days, and a named checkpoint can seed a fresh sandbox, so a session can be resumed or branched without rebuilding the environment.
ReliabilityAt zero or negative balance, sandbox create, restore and resume return 402 sandbox_balance_required; a suspended team blocks new runtime spend and file writes while pause/stop and destroy stay available. Create and mutation endpoints return 429 with Retry-After when rate-limited; retained disks expire after seven days of inactivity.
NotesHosted EU sandboxes at EUR 0.000020 per vCPU-second plus EUR 0.000004 per GiB-second; the operator's list puts the 2 vCPU/4 GB shape at USD 0.222 an hour, billed per second. The Basic team base price is free but there is no free runtime: a positive balance from a card top-up (minimum EUR 5) is required to start a sandbox, so the offer is paid-only. The 1-hour runtime limit on the pricing page conflicts with the 24-hour limit in the billing docs. No self-hosted software is offered.
