Pricenone stated
Limits
  • request-rate 100 queue workers run in parallel on one server by default (--queue-workers) source
inngest start runs Inngest as a single-node service labelled beta, and with the default SQLite database the server does not scale beyond a single node. The signing key must be a hexadecimal string with an even number of characters.
Bindingnone The self-hosting pages state no execution or event quota; the machine, Redis and the database bound throughput, and 100 queue workers run in parallel by default.
Identityanonymous No Inngest account is needed: the user creates an event key and a signing key in any format they choose (the signing key a hexadecimal string with an even number of characters) and passes them to inngest start.
Egressnot set by the software: the server invokes the user's functions over HTTPS or the Connect gateway from the machine the user runs it on, so the network terms of that host apply
Per-object capnot stated on the self-hosting pages read
Retentionthe server does not delete old PostgreSQL rows for events, runs or traces by itself, so retention is whatever the user's cleanup keeps; the default database is SQLite at ./.inngest/main.db
Interfacerest, graphql, cli the server provides GraphQL and REST APIs for programmatic access and management of system resources, with the Event API and the Dashboard UI on port 8288 and the Connect gateway on port 8289; the Inngest CLI starts it with inngest start, and the Inngest SDKs in the user's app send events with an event key and share a signing key with the server
Toolingthe user installs and runs the Inngest server on a rented or free machine: the Inngest CLI (npm install -g inngest-cli, the inngest/inngest Docker image or a release binary) started with inngest start, with SQLite and an in-memory Redis by default, or with PostgreSQL and Redis through the Docker Compose example or the Helm chart for Kubernetes; the Inngest SDKs in the user's own app.
Composes withLast resort after the hosted durable-execution offers (the hosted Inngest free tier in dev-services/inngest, then Temporal Cloud in dev-services/temporal-cloud and the n8n Cloud trial in dev-services/n8n-cloud): the user's functions still run on a host that serves them, and the server adds the queue, schedules, retries and fan-out from a machine that the user installs and keeps running.
ReliabilityInngest's support team does not guarantee direct support for self-hosted instances; inngest start is labelled beta; without external services the queue and run state live in an in-memory Redis whose snapshots are saved to SQLite periodically and at shutdown, a Docker run that does not mount the SQLite directory loses the database with the container, and PostgreSQL rows for events, runs and traces are not removed automatically.
NotesSelf-hosted software and the last resort: the hosted offers come first (the hosted Inngest free tier dev-services/inngest, the Temporal Cloud credit dev-services/temporal-cloud and the n8n Cloud trial dev-services/n8n-cloud). This record is no duplicate of dev-services/inngest: it is the server that the user installs and runs.
Evidence notedocumented Install, configuration, persistence and the interfaces are read on the first-party self-hosting documentation and the repository README; the server was not installed or run, and the self-hosting pages state no price or quota.
