Bindingper-object-cap Teldrive cannot change the object ceiling; it only hides it. At 1 TiB/month the 2 GB cap still splits every large object, and the account's upload flood limits (FLOOD_PREMIUM_WAIT_X on a non-Premium account) shape the rate.
Identityany-phone A Telegram account plus api_id/api_hash, and a PostgreSQL instance that must be run. This is software, not a hosted service.
EgressTelegram's own terms; downloads come from Telegram's media DCs, at the speed a free account is allowed.
free allowance: no allowance published
Per-object capInherits Telegram's per-object ceiling: 2 GB on a free account, 4 GB with Premium.
RetentionAs long as the Telegram account and the channel survive. The project warns: 'Accounts and stored files can become unavailable; keep independent backups.'
Interfacerest, rclone, cli 'Telegram-backed file storage with a web interface, an HTTP API, and rclone integration.' Login is by Telegram account, and channels are synced from the UI.
ToolingLinux/Windows binaries, Nix, Docker or Podman; a maintained rclone fork (tgdrive/rclone) supplies the backend. PostgreSQL is mandatory.
Composes withTurns a set of Telegram channels into one mounted filesystem, which is the only way to make the per-object cap stop being the unit of work: the user sees files, the backend shards them.
ReliabilityThe project ships its own warning: 'Follow Telegram's terms and API limits. Accounts and stored files can become unavailable; keep independent backups.' A ban takes the whole drive with it.
NotesThis is software that must be run locally, unlike every bot among debrid providers. It is included because it is the only maintained path that presents Telegram as a filesystem, and because the free compute tier can host it; abandon if the PostgreSQL requirement or the rclone fork stops being maintained.
Evidence notedocumented Requirements and the data-safety sentence are from the repository read. No instance was deployed, so the effective throughput is unmeasured.
