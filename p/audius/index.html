Upload limit is 2 GB per track. The is_downloadable flag must be true for the /download path. Direct endpoint /content/{cid} on creator nodes returns HTTP 401 to anonymous callers, requiring signed URLs from the discovery endpoint.
Identityanonymous (inferred, not read) not published
EgressFree. Content is served by creator nodes / the open-audio validator network; no egress meter, no account-level bandwidth cap, no paid tier to upgrade to.
Per-object capfile size cap is 2 GB (2000000000 bytes)
Interfacerest rest
ToolingPublic discovery-provider REST API (discoveryprovider.audius.co/v1). Keyless with app_name. Track objects expose orig_file_cid, orig_filename, is_original_available, is_downloadable. /v1/tracks/{id}/stream returns a 302 to a creator-node cidstream; /v1/tracks/{id}/download returns a 302 to the ORIGINAL file. JS SDK (@audius/sdk), docs.audius.co/api.
Composes withUnlimited tracks per account across multiple accounts, with each track capped at 2 GB. The /download endpoint serves orig_file_cid directly rather than transcoded audio, preserving uploaded bytes intact.
ReliabilityNo transcoding on the download path. Verified live: GET /v1/tracks/7AVQpPA/download -> 302 to val007.open-audio-validator.com/tracks/cidstream/<orig_file_cid>?filename=....wav -> 206, Content-Type audio/wave, Content-Disposition attachment; filename='...wav', Content-Range bytes 0-1023/54711220, body starts 'RIFF....WAVEJUNK'. The stream path, by contrast, is a 128 kbps mp3 re-encode. Retrieval depends on the discovery provider being up; the network is decentralised so a single node going down is survivable.
