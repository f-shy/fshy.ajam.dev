The same page prices the paid plans: Solo $19/mo (1 IPv4, 1 /48, 2 machines), Team $49/mo (3 IPv4, 1 /48, 6 machines), Business $149/mo (8 IPv4, 1 /48, 20 machines, verification required).

Interfacerest, cli The lease arrives as one WireGuard configuration file per tunnel, and that is the real access path; the schema's interface enum has no token for a tunnel. Ordering and management are a documented HTTP API at https://api.anchoredip.com/api/ covering plans, leases, tunnels, reverse DNS, renewal and payment, a dashboard that renders the same calls, and an MCP endpoint the pricing page names for agents. Two routing modes: 'source' writes Table = off and PostUp rules and needs wg-quick on Linux, while 'full' works in any WireGuard or AmneziaWG client.

Toolingwg-quick with the generated config in source mode, or any WireGuard or AmneziaWG client in full mode. The HTTP API creates a tunnel and returns the config once, and the vendor states the private key is not stored on its side, so it has to be written in the same step. The vendor states that a platform which cannot create a network interface, naming Heroku and Lambda, needs one small always-on machine to hold the tunnel; a Workers AI gateway is that shape, with the Worker making the calls and a VM carrying the tunnel.
Composes withPairs with a free-tier VM: the VM holds the WireGuard tunnel and everything it sends leaves as the leased address, so a Workers AI gateway behind it presents one allowlistable identity to the partner API. The lease supplies the identity and the VM supplies the kernel interface the lease needs.
ReliabilityEvery address is screened against blocklists before assignment and re-checked daily, but the trial address comes out of the same /24 as paying customers, so blocklist reputation is shared across the block. Traffic detours to Karaganda: the vendor measures 78 ms round trip to Frankfurt and 161 ms to Virginia. Outbound 25, 465 and 587 are blocked on every lease until asked. A lapsed renewal stops traffic and holds the address for 7 days before it returns to the pool.
NotesThis record corrects egress/anchoredip, whose evidence entry reads 'space registered at RIPE NCC and announced from AS41800' with no registration class. That sentence invites the reading that AnchoredIP is an ISP holding a broadband allocation. RIPE RDAP read on 2026-10-24 returns 194.0.109.0/24 with country KZ, type ASSIGNED PA and registrant lir-kz-individual-1-MNT, an individual, and the autnum object for AS41800 sits under the same registrant. That is a personal provider-independent assignment in Kazakhstan, not an eyeball network, and the announced footprint is five IPv4 /24s plus one IPv6 /29, so every tenant sits inside 1,280 addresses. The vendor's own footer says the same thing: 'AnchoredIP - AS41800 - Karaganda, Kazakhstan'. The egress record must stop implying ISP registration; this record carries the measured class. Each of three possible kinds of holder was tested for this space. (1) An ISP with a broadband allocation: refuted, because the RDAP type is ASSIGNED PA and the registrant is an individual maintenance object rather than a LIR member. (2) A hosting provider's block re-announced by AnchoredIP: refuted, because the AS registrant and the address registrant are the same person. (3) A resold block from a larger carrier: not refuted and not confirmed, because the parent 194.0.108.0-194.0.111.255 was not walked up to the LIR that allocated it. That walk was not run. Two deviations are deliberate and both come from the evidence. First, identity_cost.kind is email and not anonymous. No card and no account is right, but POST /api/leases/ requires billing_email and the API page states 'A trial is one per billing email', so the email is the key the free offer is counted against; a reader planning several trials is misled by anonymous and not by email. Second, the registrant handle reads lir-kz-individual-1-MNT in the live RDAP response; the record carries the measured string. The egress quote is on /vs/fixie and not on /pricing, which the egress record's source_url for that sentence points at. What could not be settled: which /24 a leased address actually lands in. The vendor says the trial is 'a real address out of the same /24 our paying customers are in', and its own API example shows 194.0.108.99 while the RDAP sample is 194.0.109.0/24, so more than one /24 is in use and only a live lease would fix which. The latency figures are the vendor's measurements, not ours. And this rests on one sample: one /24 was classified out of the five announced, so the other four are unverified and the class claim is a claim about 194.0.109.0/24 rather than about the whole service.
