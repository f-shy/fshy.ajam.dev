robots.txt on apibay.org carries only Cloudflare content signals and no crawl delay. The 7,200-second cache means repeated identical queries cost the origin nothing.
Bindingrequest-rate No byte quota exists on an index; the only constraint is the rate at which titles are enumerated, and it tolerated about 0.2 req/s with no throttle.
Identityanonymous No key, no account, no captcha. The site's own 'robot check' overlays are ad furniture, not an API gate.
Egressno byte allowance: JSON only; the transfer is between the user and the swarm
free allowance: none published
Per-object capnot applicable: index results
Retentionthe index keeps the row after the swarm dies; seeders and leechers are the only liveness signal in the record
Interfacerest GET /q.php?q=<query>&cat=<n> returns a JSON array; every row carries info_hash so a magnet is one string concatenation away. Responses are front-cached (Cache-Control max-age=7200).
endpoint: https://apibay.org/q.php?q=ubuntu&cat=0
ToolingOne GET and a json parse; the whole site is a thin client over this API, so a scraper of the HTML is pointless.
Composes withSearch by title, build the magnet from info_hash, then ask a debrid service for a cache hit before pulling anything.
ReliabilityThe API is served through Cloudflare with a two-hour cache, so a query can answer from cache after the swarm has gone; single-file rows report num_files 1 and a size in bytes, which is enough to filter but not to confirm the file still exists.
NotesThe cleanest no-account JSON torrent feed found: a single GET, a fixed schema, and an info hash in every row. Its political fragility is the risk, not its quota: the domain is one seizure away from gone.
