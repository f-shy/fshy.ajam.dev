Bindingwrite-gated The resolver is free, keyless and fast, and it stores nothing, so what binds is that it only resolves: there is no write path, and the pans most in demand are behind the keyed endpoint.
Identityanonymous no account, no key and no cookie for the free drivers. The professional endpoint needs an X-API-Key
EgressFree. It issues a 302 to the real CDN origin, so the bytes never traverse the resolver: verified against China Mobile EOS with X-Amz-Expires=86400
Per-object capNot applicable; it stores nothing
RetentionNot applicable. The instance caches a resolved ecpan link for 5 minutes, and the signed redirect carries X-Amz-Expires=86400, so a URL is resolved per session rather than stored (1 days)
Interfacerest
Toolingtwo public keyless forms, GET https://lz.qaiu.top/parser?url=<enc>&pwd=<pin> which 302s, or the short form https://lz.qaiu.top/ec/<key>@<pin>. A mirror at lz0.qaiu.top. Self-hostable from the repository with Docker on ports 6400 and 6401
Composes withPair with a public AList that lists share links, or with any resource site, to fetch Chinese-pan content without an account. The server software can also be installed and run on a rented or free machine, the last resort after the hosted instances
ReliabilityAlive and actively maintained, Trendshift-listed. It is the project's official free public instance. The README asks users not to over-rely on it. The README says heavy request volume can get the server limited by the pan vendors.
NotesThe single highest-leverage piece of glue in the topic and the reason the pan survey is usable at all. Two endpoints, and the split is the finding: the free one covers lanzou, ilanzou, ctfile, wenshushu, feijipan and ecpan, and the keyed one adds Baidu, Xunlei, Quark, UC, 139, 189 and Unicom.
