Free tierNo LFS storage quota is published and none is enforced in the docs. Microsoft states plainly: 'Azure DevOps Services fully supports Git LFS and offers it for free.' The free tier is 5 Basic users with unlimited private Git repos; only Azure Artifacts carries a numeric cap (2 GiB free). Repo size guidance is 250 GB (soft), 'recommend keeping below 10 GB for optimal performance'.

EgressUnmetered. No bandwidth line item exists anywhere on the Azure DevOps pricing page. The paid units are users, parallel jobs and Artifacts GiB only.
Interfacerest, ssh, git part of the text of Free tier, above
Toolinggit-lfs 3.x (gitlfs/git-lfs). Works over HTTPS; SSH is NOT supported for repos with LFS-tracked files. PAT auth. Also reachable via the Azure DevOps REST API for repo/ref management.
Composes with5 free Basic users per org, and up to 5 orgs per account (Microsoft Q&A, moderator answer) -> 25 orgs' worth of free LFS if each is a separate MSA. Orgs are unlimited in repo count, so total LFS is bounded only by the 250 GB-per-repo soft guidance. 250 GB x N repos. Unlike GitLab/GitHub, LFS bytes are not on the meter at all.
ReliabilityThe 250 GB repo figure is guidance, not a wall, but the docs warn the internal pack-file limit can trigger 'The Git pack file limit has been reached' and temporarily block writes on very large repos. Over-quota behaviour is undefined because there is no quota.
