Free tier$2,000 (USD) in donated Azure services credits per year, renewable. Not a byte quota. A credit grant usable against 'the complete portfolio of Azure products and cloud services', which includes Blob Storage / Data Lake Storage Gen2 / Azure Files.

Per-object-cap: Blob block blob max ~190.7 TiB, single PUT 5,000 MiB. Not the constraint. The constraint is budget: the grant is a spend cap, and any per-GB/month rate times 10 TiB must fit inside $2,000/yr. request-rate: standard storage account limits (20,000 IOPS-class). retention: balance expires at the annual renewal date; 'Early consumption of the $2,000 balance does not trigger or permit early renewal'.
Identitycard (inferred, not read) not published
EgressAzure egress is metered and would eat the credit; this only works as archive (rare read) or behind a CDN whose own free tier covers delivery. Archive-tier reads also carry retrieval cost.
Per-object capper-object-cap: Blob block blob max ~190.7 TiB (209676867416883 bytes)
Interfaces3-compatible, rclone, cli s3
ToolingNative Azure API, not S3: rclone backend 'azureblob' (Tier 1, chunked, server-side copy), AzCopy, Azure CLI, BlobFuse for POSIX. Azure does not expose an S3-compatible endpoint on Blob Storage.
Composes withRenews annually at $2,000 ('All Azure Sponsorships renew at $2,000 USD per year'), so it is a recurring grant, not a trial. But the balance is annual, so the multiplier is $2,000 x years x number of verified nonprofit tenants. Renewal must be done manually in the Nonprofit Hub between 30 days before and the expiry date, or usage converts to pay-as-you-go against the stored payment instrument.
ReliabilityMissing the renewal window silently converts the subscription to pay-as-you-go and starts charging the payment instrument on file. A real cost hazard, not a data-loss hazard.
