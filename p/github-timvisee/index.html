Per-object-cap: the table's Size limit column (2.5 GiB to 250 GiB). Retention: the Time limit column (3 to 30 days), MAX_EXPIRE_SECONDS on the server. pull-count: the DL limit column. Adminforge allows 1,000, hostnetwork 999,999, but most sit at 10-100. The pull cap, not bytes, is the real bind on the E8 workload.

ToolingFfsend (github.com/timvisee/ffsend). Real CLI with --host URL. Server is a self-hostable Rust binary, so the config (MAX_FILE_SIZE, MAX_EXPIRE_SECONDS) is public per instance.
Composes with15+ public instances in the table, each an independent operator with its own quota => shard across instances rather than accounts. Since the server is self-hostable, the ceiling on an instance you run is only your own disk.
ReliabilityAll files are E2E encrypted client-side and deleted on expiry; no originals re-encode.
