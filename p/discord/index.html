Free tierNo total storage cap documented anywhere. Per-file only: 20 MiB per attachment on a free account since 2026-09-03 (raised from 10 MiB). 10 files per message. Server Boost tiers raise it for all members in that server: Tier 2 = 50 MB, Tier 3 = 100 MB; Nitro Basic 50 MB, Nitro 500 MB (1 GB per the Nitro marketing page).
unit objects; metered on stored-bytes
Pricenone stated
Limits
  • per-object-cap (binding) 20 MiB per file source
20 MiB per file is the hard bite. Message create is ~5 messages / 5 s per channel; global ~50 req/s per token; 10,000 invalid requests per 10 min triggers a 24 h Cloudflare ban. Attachment URLs carry ex/is/hm and stop working after 24 h. See reliability_note.
Identityinstitution (inferred, not read) not published
EgressUnmetered and free. Cdn.discordapp.com is Cloudflare-fronted and there is no bandwidth metering or egress billing of any kind. This is the strongest egress position in the whole survey.
Per-object cap20 MiB per file (20971520 bytes)
Retention| Attachment CDN URLs are signed and expire in exactly 24 h; the bytes stay on Discord's servers indefinitely but the link must be re-derived via POST /api/v10/attachments/refresh-urls (401 without a token) or by re-reading the message
Interfacerest, rclone rest
ToolingOfficial Bot HTTP API (POST /channels/{id}/messages with files[], or the two-step cloud-upload path). Mature wrappers: forscht/ddrive (533 stars, Discord-as-filesystem with REST + OpenAPI 3.1), missuo/discord-image (212 stars, Go, refreshes CDN links), ShufflePerson/Discord_CDN (link refresher proxy), DisboxApp/server. No rclone backend.
Composes with100 servers per free account (200 with Nitro) x 500 channels per server = 50,000 text channels per account, and every channel takes unlimited messages. This is the multiplier: not per-file size but per-message count. ddrive's author reports storing 4,000 GB in a single Discord channel, so the practical ceiling is account count x rate limit, not storage.
ReliabilityAttachment CDN URLs are signed and expire in exactly 24 h; the bytes stay on Discord's servers indefinitely but the link must be re-derived via POST /api/v10/attachments/refresh-urls (401 without a token) or by re-reading the message. Any un-refreshed link returns 404 'This content is no longer available.'
