The instance reports 201 local videos totalling 21,058,245,956 bytes with 2 registered users, so the operator's disk holds about 21 GB of other people's content. Two users and 21 GB is the scale of the goodwill a 50 GiB quota is drawn on
Bindingper-object-cap Storage allowance is 50 GiB per account with no daily cap. What binds is video transcoding. Ingested files are re-encoded and return modified bytes, functioning as video hosting rather than exact byte storage.
Identityemail an email address, and the instance does not verify it: signup.requiresEmailVerification is false and requiresApproval is false. No card, no phone
EgressFree and unmetered: downloads are enabled by default (publish.downloadEnabled true) and there is no egress line item. HLS is enabled and splitAudioAndVideo is false, so the stream is a single rendition set
Per-object capNot published as a byte cap. The instance transcodes to 720, 1080 and 2160 and sets alwaysTranscodeOriginalResolution true, so the file that comes back is a transcode and not the bytes that were uploaded
RetentionNo stated expiry while the instance runs. The instance is a volunteer-run server with a single administrator and a 2026-10-14 asset date. Retention depends on ongoing server operation.
Interfacerest the PeerTube REST API at /api/v1, with open registration and no token required to read the config or list videos; upload needs an account and a token
Toolingany HTTP client against /api/v1. PeerTube's own client and third-party uploaders work; there is no rclone backend and no WebDAV, so a pipeline is the upload API or nothing
Composes withA 50 GiB per-account tier with no daily cap is the largest video-platform allocation found and it does not chain into a storage stack, because the read path returns a transcode. Its role would be as a distribution surface for content that is already video, and not as a store for arbitrary bytes
ReliabilityA single-admin volunteer instance in France with two registered users and 39 followers. The config carries a custom support banner and an a-ads iframe, so it is ad-funded and personal. An instance of this size disappears with one hosting decision
NotesActive instance provides 50 GiB per user with no daily cap and open registration without email verification. Uploaded media is transcoded on ingest, returning re-encoded renditions rather than original files.
