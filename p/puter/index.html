ToolingPuter.js. A single <script> tag or the @heyputer/puter.js npm module, keyless. puter.fs.write / read / mkdir give a browser-side filesystem API; auth is 'sign in with Puter'. No S3/WebDAV/SFTP shim.
Composes withThe interesting multiplier is the opposite of the usual one: because storage is metered to each signed-in user's account, an app with N users gets N x (that user's allowance) and the developer pays nothing. But the free allowance per user is 25 MB, so the chain only works if the app also controls the user accounts. I.e. it is a way to make storage free for an app's users, not a way to get 10 TiB.
ReliabilityExplicitly blocks the several-accounts route: Puter markets that 'usage is metered to each user's own account, so a bad actor has no free resources to farm', plus automated-signup filtering. That removes the second-account allowance this niche usually relies on.
