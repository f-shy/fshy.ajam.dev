Bulk path: API v2 fred/v2/release/observations returns every series on a release with its entire history, 500,000 observations a call with next_cursor paging; one series is also a keyless CSV at fredgraph.csv.
Bindingrequest-rate No daily or monthly count is published, so the 120 per minute throttle is the only stated ceiling; v2 release pulls of 500,000 observations a call keep it far away.
Identityemail Every API request needs a key, and a key is requested from a fredaccount.stlouisfed.org account. The account asks only for a valid email address and a password, and is active as soon as the form is submitted; no card, no phone. The keyless fredgraph.csv download and the website need no account.
Egressnot metered in bytes; the 120 requests per minute bound what a key can pull
Per-object cap100,000 observations per v1 series/observations call; 500,000 observations per v2 release/observations call
Interfacerest v1: GET https://api.stlouisfed.org/fred/... with api_key (a 32-character lower-case key) as a query parameter, JSON or XML. v2: GET https://api.stlouisfed.org/fred/v2/release/observations with the key in an Authorization: Bearer header and next_cursor paging. A call with no key answered HTTP 400.
endpoint: https://api.stlouisfed.org/fred
Toolingcurl or any HTTP client; fredgraph.csv serves one series as CSV with no key
Composes withWhole economic releases in one paged v2 pull at no cost; it pairs with a market source such as Tiingo or CoinGecko when macro series sit beside prices.
ReliabilityPast 120 requests a minute the API answers HTTP 429, and ignoring the throttle can bring a temporary block; an error answer is an HTTP status with an XML or JSON body that carries the error.
NotesFree with an email-only key, no stated daily or monthly count, and a documented bulk path (v2 release observations). The series notes name them.
