Limits
  • request-rate none published by rclone; the upstream Premiumize rate limit is unpublished and surfaces as a 200-with-rate_limit_reached envelope the backend must interpret source
Read-only: no upload path exists in this backend, so a workflow that writes into debrid cloud cannot use it.
Bindingnone The client imposes nothing; at 1 TiB/month the binding constraint is the Premiumize fair-use meter, not the mount.
Identityanonymous No registration with rclone; it inherits the debrid account's identity. Installing it needs no account at all.
Egressrclone does not meter or bill; it reads through the debrid account and therefore spends that account's fair-use budget.
free allowance: none of its own
Per-object capnot applicable to the caller; the object cap is the debrid account's.
Retentionnot applicable: a mount reflects the remote's contents live.
Interfacerclone, webdav Configured with 'rclone config' -> 'premiumizeme'; authentication is an interactive OAuth token in a browser, not the raw API key, so a headless box needs the token copied in. The backend is read-only.
endpoint: https://www.premiumize.me/api
Toolingrclone itself, plus anything that speaks to an rclone mount: Plex, Jellyfin, Emby, restic, rsync over the mount.
Composes withThis is the only direct, first-party path from a plain Unix command to any of the eight services: 'rclone mount premiumizeme:' and published records has a filesystem, with no zurg, no shim and no container.
ReliabilityA mount is only as stable as the upstream API; a Premiumize throttle comes back as a success-shaped JSON envelope and shows up as a stalled read rather than an error.
NotesNamed as a separate record because 'which debrid service has an rclone backend' is a question six of the eight answer 'none' and one answers 'yes'. Trigger condition: a real-debrid or torbox backend landing in rclone makes this record a comparison, not a singleton.
