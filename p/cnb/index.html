Free tierPer top-level org, free tier per month: '仓库存储 100 GiB' + '对象存储 100 GiB' (object storage covers '制品、LFS 对象、图片及附件'), plus 160 build-CPU core-hours and 1600 dev-CPU core-hours. Over-quota is metered at ¥1/GiB/month, and storage is billed on daily average minus the free allowance. So staying under 100+100 GiB per org is genuinely free.
unit GiB; metered on stored-bytes
Pricenone stated
Limits
  • per-object-cap (binding) 256 MB per file source
Per-object-cap: 64 GB per release/commit attachment (provider's own plugin README: '目前暂支持 64GB 以内的文件上传'). repo-blob cap: 256 MB per file in the git tree, with the maintainers explicitly steering large files to release attachments ('此256M之限制..当以附件方式为之'). request-rate: none documented. Billing: over the free 100 GiB the org is charged ¥1/GiB/month at month start. Silent overage, not a hard stop.
Identitynational-id national-id (WeChat login / 腾讯云 account; the docs' usage-management flow binds a Tencent Cloud budget). Not anonymous.
EgressPricing table specifies 仓库存储 and 对象存储 by GiB-month without a separate egress traffic row. Public release-attachment downloads run through the cnb.cool CDN.
Per-object cap256 MB per file (256000000 bytes)
Interfacerest, webdav, webdav-proxy, cli rest
ToolingOpenList ships a first-class cnb_releases driver (github.com/OpenListTeam/OpenList, drivers/cnb_releases. Fields: repo, token, use_tag_name, default_branch), i.e. a maintained WebDAV/HTTP front end over CNB release attachments. Also the official cnbcool/attachments plugin ('支持 commit 和 release 上传或下载附件，目前暂支持 64GB 以内的文件上传') and a Rust CLI (cnb release download/--share).
Composes withFree allowance is per top-level organization ('每个顶级组织独立计费') providing 200 GiB each. Repositories support releases with attachments up to 64 GB per file.
ReliabilityCommunity edition launched public beta 2025-08; beta-free extras expired 2025-08-31, so the 100+100 GiB figures are the steady state. No ban/wipe reports found; overage is billed rather than blocked, which is the real hazard.
