Free tierNo free tier is documented: a third-party review checked in October 2026 states that search and downloads require an active subscription, and a comparison table lists NZBGeek's free tier as 'None (subscription required)'. An unkeyed search is refused with an empty-API-key error and caps declares registration available=no. Earlier third-party readings of a free trial and of a few downloads a day are not found on the pages read now. The public site lists no prices.
unit requests; metered on request-count; The conservative reading is the one the vendor's own API supports: an unkeyed call is refused, and no reading of the free tier describes an API allowance enough to drive an arr stack. The 5-calls-a-day figure is unsourced, not contradicted.

  • request-rate (binding) no free API allowance that a stack can use; paid membership USD 12/year source
  • request-rate (binding) 100 results per request maximum (caps <limits max="100"/>) source
The 100 is a per-request result ceiling and applies to every tier; it is not the paid allowance.
Bindingrequest-rate The API call allowance is what fails first: without a key the first automated search is refused outright (error 102), and the readings of the free tier that describe an allowance put it at 5 calls a day, which is one search every five hours.
Identityemail Registration is contradictory at the vendor: the login page links 'register account?' and register.php serves a Registration Agreement with an 'agree' submit, while /api?t=caps declares <registration available="no" open="no"/>; a third-party review checked in October 2026 states that registration was open. The fields a signup demands are unverified: behind a sign-up.
EgressNo byte metering: the API returns XML pointers. The payload is served by whichever news provider is paid for.
Per-object capnot applicable: an NZB pointer file
Retentionnot stated on the API surface. A third-party listing claims 'NZBs from 8 years ago available, 500,000+ indexed NZBs' (nzbhydra.com, 2026-10-23).
Interfacerest Newznab API on a separate host, api.nzbgeek.info/api, not nzbgeek.info/api (the apex returns HTML). caps declares <limits max="100" default="100"/> and <registration available="no" open="no"/>. An unkeyed search returns error code 102.
endpoint: https://api.nzbgeek.info/api?t=caps ; https://api.nzbgeek.info/api?t=search&q=<query>&apikey=<key>
ToolingNative Newznab: Prowlarr, NZBHydra2, Sonarr, Radarr, Lidarr and Mylar all add it with URL plus key. No wrapper needed. The API host is different from the site host, which is the first mistake a hand-rolled config makes.
Composes withA broad, well-populated index that a paid arr stack reaches with no wrapper; on the free tier it contributes nothing to automation, because no reading of the free tier gives an API allowance that could drive a stack.
ReliabilityThe membership is what keeps the index alive; a lapsed membership drops the account back to the capped tier and automation stops with no partial service.
NotesTwo vendor signals contradict each other on registration: a served agreement form says open, caps says available=no. The conservative reading is recorded on the record and not resolved, because resolving it needs an account. The verdict rests on the API allowance, which is independent of that question.
Evidence notereported The caps and the unkeyed error were measured. Creating one free account and reading its API page would move this to documented.
