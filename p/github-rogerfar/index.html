  • request-rate none of its own; its polling interval is the provider's problem, and its own issue tracker carries reports of it treating client-side retries as provider 429s source
The project's issue #952 documents a client-side false 429: 'Evidence this isn't a real RD 429 ... Direct curl from inside the container with the same API key ... all return 200. 30 rapid-fire calls in a row to /torrents also return 200.' A retry layer can invent a throttle that the provider never sent.
Bindingnone A pure client: the provider's per-object cap or add floor fails first.
Identityanonymous No account with the project; it stores the provider's key.
EgressDownloads the files to the local machine ('Download all files from Real-Debrid, AllDebrid, Premiumize, TorBox or HIGHWAY to your local machine automatically'), so it converts unmetered provider egress into local disk use.
free allowance: none of its own
Per-object capnot applicable to the caller; the provider's cap applies.
Retentionnot applicable: it manages the provider's torrent and usenet lists and deletes completed items locally after download.
Interfacerest Web UI plus 'a fake qBittorrent API so you can hook up other applications like Sonarr, Radarr or Couchpotato'. Built on .NET 10 and Angular 21; runs as a Windows or Linux service or in Docker.
endpoint: unverified: the project's default web port was not read; the service is configured through appsettings.json
ToolingDocker, Windows service, Linux service; Sonarr, Radarr and Couchpotato as downstream clients.
Composes withThe download-to-disk counterpart to Decypharr's stream-in-place: Sonarr grabs through it, it fetches from the provider, unpacks, and leaves a normal file where the *arr stack expects one.
ReliabilityIts Polly retry pipeline has produced 429 warnings at ~10 ms execution time, which is too fast to be a network round trip; the log says throttled while the provider is healthy.
NotesNamed separately from Decypharr because the two make different tradeoffs: rdt-client downloads to disk, Decypharr serves in place over NFS/SMB. The client-side false-429 finding belongs to the user, not to Real-Debrid.
