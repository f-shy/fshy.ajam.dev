- binding note: The 250-message-per-day ceiling keyed to IP address is the first threshold a script reaches at normal alerting volume, before the 60-request burst rate or the 200 MB bandwidth budget.
- interface detail: Publishing is an HTTP PUT or POST to ntfy.sh/<topic> with the message as the body and headers for title, priority, tags and attachments. Subscribing uses a GET streaming API at <topic>/json, <topic>/sse or <topic>/raw, or WebSockets at <topic>/ws, all documented. The ntfy CLI publishes and subscribes from a shell. A free anonymous user publishes to any unreserved topic name with no authentication, so the topic name acts as the credential.
- endpoint: https://ntfy.sh
- tooling: curl or any HTTP client for PUT/POST publishing; the ntfy CLI; official client libraries for JavaScript, Go, Python, PHP and PowerShell shown in the docs; official Android, iOS and web apps for receiving. Client SDKs exist for common languages.
- composes with: A worker or script on any free compute service sends one HTTP PUT/POST to ntfy.sh to reach subscribed phones and desktops; healthchecks.io, GitHub Actions, Ansible, Home Assistant and Uptime Kuma are named integrations.
- reliability: Best effort only: the FAQ states the service runs on a single DigitalOcean droplet without scale out or redundancy; short blips and HTTP 500 spikes have occurred. Traffic over the daily bandwidth budget returns HTTP 429 (error code 42905). Repeatedly exceeding limits may temporarily ban the IP address.
- notes: ntfy has both a hosted free server (ntfy.sh) and self-hostable open-source software; this record documents the hosted free offer, not the self-hosted software, so self_hosted is absent.
