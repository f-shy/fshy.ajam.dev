Canonical URLs 302 at least once (clients need --location-trusted when sending Authorization); do NOT link iaNNNNNN.us.archive.org directly (nodes move); 429/503 under load; no auth on GET, so everything is world-readable.
Bindingper-ip-shaping one stream is shaped, and aggregate throughput is the shaped rate times the number of streams
Identityanonymous no credential is needed to read: an anonymous GET of archive.org/download/<identifier>/<filename> redirects once to a datanode and serves the file. Uploading needs an Internet Archive account whose form asks an email address, a screen name and a password, and asks no phone number
EgressFree / unmetered. Docs: 'high performance downloads are achieved via the archive web infrastructure'. I.e. GET https://archive.org/download/<item>/<file>, which 302s to an iaNNNNNN.us.archive.org datanode. BitTorrent webseeds supplement it.
Interfacerest, rclone, cli rest
Toolingplain HTTPS GET with Range (measured: 206 + accept-ranges: bytes); ia CLI download w/ --checksum resume; rclone 'internetarchive' reads back through the same front end
Composes withParallelising across items distributes traffic across different iaNNNNNN datanodes, scaling aggregate throughput with item count rather than single-item connections. Fronting with Cloudflare caching (replay responses carry cache-control: max-age=1800) shields origin nodes from repeated requests.
ReliabilityThroughput is shaped server-side: measurements showed 1.19 MB/s on a single stream and 1.66 MB/s aggregate across 8 parallel range requests to a single datanode (~145 GB per day). Local link speed measured at 27.6 MB/s.
