Free tierEach project in a Free tier namespace on GitLab.com has 10 GiB of free storage for the project's repository and LFS. A project in a Premium or Ultimate tier has 500 GiB. The container registry, package registry and build artifacts are not included in the limit. Whether snippets, uploads and wikis count: unverified, the page does not say.

Egressunverified: no egress charge or volume quota is stated on the pages read. The only transfer-side control stated is a request rate: on GitLab.com Git LFS requests are subject to the authenticated web request rate limit of 1000 requests per minute per user, and each Git LFS object uploaded or downloaded generates one HTTP request.
Per-object capunverified: no per-object limit for Git LFS objects is stated on the pages read. Related limits: git push and project imports are limited to 5 GiB for each request through Cloudflare; maximum attachment size is 100 MiB.
Interfacegit git-lfs over HTTPS
Toolinggit-lfs. Also Oras-style raw access is not available; LFS is protocol-only. GitLab REST API v4 for project/namespace management (useful for automating project-per-shard).
Composes withEach project in a Free tier namespace on GitLab.com has its own 10 GiB of free storage for the project's repository and LFS. The number of projects allowed per namespace or account: unverified, the pages read state no limit and no cap.
ReliabilityRead-only state is reversible only by purchasing storage, so a blown project is stuck. The 1000 req/min limit bites hard on many-small-files datasets during clone, and GitLab's own docs warn multi-file projects 'may encounter an HTTP rate limit error' in CI.
