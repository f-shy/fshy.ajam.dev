5 GB per file (Generic / Maven / npm / NuGet / PyPI / Conan); 10 GB for ML models (upload capped at 5 GB); 1 GB for Terraform state; Helm only 5 MB. Anonymous read of public project packages; writes need a token. Repository/LFS Git push limited to 5 GiB per request, irrelevant to packages.
Identityinstitution (inferred, not read) not published
EgressFree and Cloudflare-fronted. GitLab.com is behind Cloudflare and blobs are served from Google Cloud Storage / the GitLab CDN (cdn.registry.gitlab-static.net). No egress billing for public projects.
Per-object cap5 GB maximum per upload (5000000000 bytes)
RetentionArtifacts expire in 30 days, packages do not. (30 days)
Interfacerest, cli rest
ToolingGitLab REST API v4 (PUT /projects/:id/packages/generic/:package_name/:version/:file_name, GET ../package_files/:id/download), glab CLI, python-gitlab (has generic package support, merged), goreleaser pushes generic packages natively (PR #2745 merged). Works with plain curl. No special client needed.
Composes withUnlimited projects per namespace (no project-count cap is documented on GitLab.com; the only new limits are 3 top-level groups for accounts created after 2026-01-27, and the personal namespace does not count). Each project is its own unbounded package bucket at 5 GB/file. N projects x unlimited package versions x 5 GB. Multiply again by additional free namespaces (3 groups + personal) and by unlimited free accounts.
ReliabilitySnippets, packages and job artifacts count toward namespace storage as a display/billing figure but are not enforced as a cap. Enforcement is per-project on repo+LFS only. GitLab could start enforcing namespace storage at any time; it has never done so for packages. Artifacts expire in 30 days, packages do not.
