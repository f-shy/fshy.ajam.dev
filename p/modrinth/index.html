500 MiB/version-file; 150 version uploads/day; 10,000 versions per project; 256 projects; version_number must be unique per project (1-32 chars); moderation may reject non-mod content; project file type must be in project_file_type allowlist (jar/zip/mrpack etc.), so arbitrary blobs need wrapping.
Bindingrequest-rate calls are bounded rather than bytes, which is fatal to a nightly job on a monthly counter
Identityemail (placeholder) not published
EgressFree. All files served from cdn.modrinth.com behind Cloudflare with Accept-Ranges: bytes, no auth, no signed URLs, no expiry.
Interfacerest, rclone rest
ToolingDocumented public REST API v2 (api.modrinth.com/v2/project/{id}/version, POST /version with multipart file upload + PAT auth); labrinth OpenAPI spec published at docs.modrinth.com. No rclone backend, but the API is simple enough for a dozen-line client.
Composes with256 projects x 10,000 versions/project x 500 MiB = ~1.22 PiB theoretical per account; practically throttled by versions_per_day=150 -> 150 x 500 MiB = 73 GiB/day/account = ~2.2 TiB/month/account. Unlimited free accounts; each new account resets all four counters. Idle accounts keep all existing files downloadable forever (no TTL on published versions).
ReliabilityModerated registry: junk projects can be removed and files hard-deleted; no rate-limit survival guarantee past 150 uploads/day.
