Free tierNo published storage quota. The user guide states the instance 'can be used by anybody to freely create binaries for any of the supported distributions' and that 'You can store your sources there, build your packages and got them mirrored around the world.' The only quantitative ceilings found are per-file/per-build, not per-project: build disk constraint is expressed as Constraint: hardware:disk:size unit=G <N> and users are seen requesting 110 GB for one build (openSUSE forum, 2026-06-16). Observed real object size in the archive: openSUSE:Factory/kernel-source/linux-7.2.tar.xz is 160,068,116 bytes, served publicly.

IMPORTANT: Range requests are NOT honoured on the source endpoint (a bounded 1 MB range GET returned 200 with the full 160,068,116 bytes), so ranged/parallel fetch must be done against download.opensuse.org (mirror ring), not api.opensuse.org.

Interfacerest, cli rest
Toolingosc (CLI, in every openSUSE repo), OBS REST API (api.opensuse.org/public/... for anonymous reads, XML), and plain HTTPS download of published repositories from download.opensuse.org. osc add $URL stores a remote-source reference; osc commit uploads real blobs.
Composes withunlimited home projects (home:<user>:<sub>) x unlimited packages per project x unlimited versions; published repos additionally replicate to every download.opensuse.org mirror at no cost. Sources are retained per package revision (the API exposes rev/vrev, e.g. osc 'rev=517 vrev=485'), so a single package with N commits holds N copies of the blob server-side. Multiply by unlimited free openSUSE accounts. This is the packaging-native equivalent of GitHub Releases, with a global mirror CDN attached.
ReliabilityAPI source endpoint silently ignores Range and streams the whole object - will blow up any client that assumes 206. Home projects are explicitly deprioritised: 'home repos are by default low hanging fruit, other projects take priority'. Recorded here only to note the 160 MB verified object and the no-Range behaviour.
