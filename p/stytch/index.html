Free tierAlways free: 10,000 monthly active users and AI agents, unlimited organizations, 5 SSO or SCIM connections and 1,000 M2M tokens; usage beyond is billed pay as you go with no hard cap
unit users; metered on identity-count; A project has one Live and one Test environment by default. In the Live environment some endpoints answer billing_not_verified until credit card details are added, and the error reference names none of them; email goes only to the sign-up address or addresses on its domain until then, which a Stytch staff reply of 2024-11-14 on its forum applies to a Test environment too. SMS and WhatsApp are enabled for United States and Canada numbers by default, and other countries need an allowlist entry and credit card details. Dashboard seats are unlimited.

Limits
  • volume-quota 10,000 monthly active users and AI agents, 5 SSO or SCIM connections, 1,000 M2M tokens source
  • write-gated (binding) Live environment endpoints answer billing_not_verified until credit card details are added, and the error reference names none of them; email goes only to the sign-up address or addresses on its domain until then (billing_not_verified_for_email); the B2B country code allowlist cannot be updated until credit card details are added, and enabling SMS to countries beyond the United States and Canada needs them too source
  • request-rate SMS OTP sends from Test environments: 60 per hour per project source
  • per-object-cap a metadata object holds at most 20 top-level keys and 4KB source
Bindingwrite-gated Without a card on file the Live environment cannot email arbitrary users, so a public app with email login meets the card gate before the 10,000 MAU allowance.
Identitycard Sign-up takes a Google, GitHub or single sign-on login or an email address, and the sign-up flow asks which authentication type to set up, such as B2B Authentication, before it creates a first project. The Test environment works without payment details; Live-environment endpoints answer billing_not_verified until credit card details are added, and email to addresses outside the sign-up domain needs them too, in a Test environment as well. Whether a later step asks for a phone number is unverified: behind a sign-up.
Egressnot applicable: an authentication API; no traffic allowance or egress term is published

Retentionunverified: no data or log retention period is stated on the pages read
Interfacerest REST API with JSON responses and HTTP Basic auth (project_id and secret); Test environments at test.stytch.com and the Live environment at api.stytch.com. A GET to a user on test.stytch.com without credentials answered 400 invalid_authorization_header. An OpenID configuration endpoint per project for Connected Apps implements OpenID Connect discovery and lists the OAuth 2.0 grant types supported.
endpoint: https://api.stytch.com/v1
ToolingStytch backend SDKs for Node, Python, Ruby, Go and Java, front-end SDKs, or any HTTP client with Basic auth.
