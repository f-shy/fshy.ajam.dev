The site describes a generated link as bound to the IP that requested it ('locked and only accessible to the user that initiated the link generator' on the sibling site). A link is therefore not portable between machines.
Bindingpull-count Eight links a day fails long before any byte total at 1 TiB of monthly transfer, if the host files are large at all. The byte ceiling is unstated, so pull-count is the only number a user can plan against.
Identityanonymous No account or login on the generator; the page advertises free use with no registration. Nothing but the caller's IP is presented.
EgressDownloads are served from DebridHub's own servers at '100% maximum speeds'. No byte allowance and no price appear on the page.

Interfaceunknown A single web form: paste the host URL, press generate, receive a link. The FAQ claims '+100 cloud platforms'. No API, key or CLI is published.
Toolingbrowser only. A wrapper would have to POST the form; the request shape was not read.
Composes withA zero-identity leecher for the occasional file on a host not subscribed to. Eight links a day is enough for a handful of files and useless for a queue, so it sits beside a paid debrid rather than replacing it.
ReliabilityIP-locked links mean a VPN change or a CGNAT egress breaks the generated link mid-download; the site states no refund or retry path because nothing was paid.
NotesDebridHub and OkDebrid publish near-identical copy, feature lists and the same 8-links-a-day cap. They are either one operator running two fronts or one template sold twice; published records both because a user will meet both names.
Evidence notedocumented The vendor's own FAQ states the daily cap. A completed download through a generated link would raise this to measured, and would also establish whether large files actually pass.
