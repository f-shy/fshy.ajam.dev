Free tierNo account and no key. GET /api/search?q=linux returned 7,318 bytes of JSON: 25 items, totalElements 4,348 over 174 pages. GET /download/<item-id>.nzb returned a 4,264-byte NZB. The route is what the site's own single-page app calls; no API documentation was found on any page reached.
unit unlimited; metered on none; No quota is published, and no account exists to attach one to. 6 rapid requests and 1 download in one session produced no 429.

Page size is fixed at 25 in the JSON the app consumes (data.page.size = 25); there is no limit parameter to raise it.
Bindingnone No byte counter, no daily cap, no account. At 1 TiB/month the indexer is not the constraint; the news provider's retention is, and a missing post costs a failed grab rather than a quota.
Identityanonymous Nothing is collected: both the JSON search and the NZB download answered without a cookie, header or key.
EgressNo metering. The JSON is a result list and the download is an XML pointer file measured at 4,264 bytes.
Per-object capnot applicable: the answer is an NZB pointer file (4,264 bytes), never the payload
Retentionnot stated on the pages read. A third-party indexer comparison claims 'approximately 1,900 days retention, 900+ newsgroups indexed' (nzbhydra.com, 2026-10-23).
Interfacerest The search page is a client-rendered Next.js app: /search?q=linux returns 8,702 bytes of HTML shell with zero results and an empty query state. The real interface is GET /api/search?q=<query>, which returns JSON with data.content[] and data.page{size,number,totalElements,totalPages}. NZB download is GET /download/<item-id>.nzb.
endpoint: https://www.nzbindex.com/api/search?q=<query> ; https://www.nzbindex.com/download/<id>.nzb
ToolingNo Newznab endpoint, so Prowlarr, NZBHydra2, Sonarr and Radarr cannot add it directly. A wrapper is small: one GET for JSON, one GET per download, both unauthenticated. The JSON route is undocumented and can change with any front-end deploy, which is the maintenance cost.
Composes withA second unnamed fallback beside Binsearch, and the only one of the three open engines with a JSON answer, so it is the easiest to wrap and the one to poll when a name has to be resolved without an account.
ReliabilityAdvertiser-supported; the JSON route is an internal app call, so a front-end deploy can move or rename it without notice, and a scrape that depended on it fails silently as an empty result list.
NotesAdding ?x=1 made the path valid and the download worked.
Evidence notemeasured Search and download were run today with status, byte count and digest recorded. The undocumented route is the fragility, not the confidence rung: it worked when measured and may not tomorrow.
