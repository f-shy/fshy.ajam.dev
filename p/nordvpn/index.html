NotesWhat the record establishes, and what it refuses to. The 7,193 figure is a node count: the same response holds 775 distinct /24s, so 7,193 servers over 25 ASNs is a ratio of about 288, and a document that reads the server count as an address count overstates the reachable networks by 288x. First, the connection ceiling is 10, not 8, and there is no Shared tier with an 8-connection cap: the pricing page reads Ten simultaneous connections on ten devices secured with one NordVPN account, the support article reads You can connect up to 10 devices to a single NordVPN account at the same time, and the app's own error text reads If you're connected on 10 devices, first disconnect one of them. Three independent first-party sources agreeing is why the number in limits is ten. The qualifier that makes it bite is the per-server rule: a shared server takes at most five devices, one per protocol, so ten connections over one server is not ten exits. Reproduced before writing this record, not relayed: a fresh fetch of the API returned HTTP 200 and 26,946,981 bytes, 7,193 server records, 150 country codes and 775 distinct /24s from the station fields, and five sampled prefixes re-resolved through RIPE to the same ASNs the stored table carries. What that reproduction does not do is re-run all 775 lookups, so the 25-ASN count and the 347 /24s in AS212238 rest on the stored table plus a five-prefix spot check. The dedicated-IP feature page answered 403 outright and is cited for the add-on shape only, on the pricing table's Add at checkout row. Candidate 2 is the live one and it is the one this record cannot close: the measurement is a single fetch of the list on one day, resolved through RIPE, and the pool as handed out at connect time was never observed. The caveat in the verdict is therefore the concentration, not the price: 45% of the shared fleet and 155 of 209 dedicated-IP /24s sit in the same ASN, so a NordVPN exit and a Proton exit can land in the same ASN. The Dedicated IP narrows the pool to 12 ASNs and does not leave AS212238, and its price is unpublished on the pages read, so it cannot be priced into a recommendation. Two attributions this record makes from a neighbour rather than from a page: the datacenter reading of AS212238, whose holder CDNEXT Datacamp Limited is named in ip-proxy/protonvpn-exits, and the Proton comparison itself, which is that record's measured exit. The interface array carries only rest because the schema's enum has no token for socks5, http-proxy, wireguard or openvpn; four sibling records in this topic already fail the gate on exactly that, and interface_detail names the protocols instead of breaking validation.
