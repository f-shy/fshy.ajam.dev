Two further constraints were found that name no vocabulary kind, so they are kept here rather than forced into one. First, yield: of 100 sampled addresses, 38 completed a handshake and 32 carried a payload, and five minutes later 34 and 30, so about 70% of the list cannot move a byte at the moment it is pulled. Second, attribution: the response carries no ASN field, so there is no way to know whose network an address belongs to without spending a request on it. That absence is what puts rung 5 out of reach before the first use.
Bindingrequest-rate The response is capped at 2,000 rows against an advertised 20,000+, so the ceiling that can be reached is the size of one response, not the size of the published pool; that cap arrives before any byte quota, which does not exist, and before any per-address shaping, which no evidence here shows. The 30% payload rate then cuts the working set to roughly 600 addresses, which is the figure that actually decides the gateway, but it is a yield property of the addresses rather than a limit the vendor sets.

ToolingA single curl, or any HTTP client, pulls the list; no account, key, SDK or wrapper is involved. Using an address afterwards needs a client that speaks the protocol it is published under (SOCKS5, SOCKS4, or HTTP CONNECT), which curl and rclone both do natively.
Composes withIt is a supply of last-resort egress addresses for the Workers AI gateway: a request a Worker cannot make from its own address is retried through a published address, at roughly a 30% payload rate and with an exit network nobody has identified.
ReliabilityThe addresses are open proxies of unknown ownership: 32 of 100 sampled carried a payload and 30 of 100 five minutes later, the response publishes no ASN field, and the exit network is therefore unknown until an address is actually used.
NotesOperational characteristics and reliability measurements for the ProxyScrape free proxy list. While website marketing claims over 20,000 proxies, API endpoints return a fixed cap of 2,000 rows per request. Responses contain raw host and port entries without ASN or network metadata annotations. Payload yield testing on 2026-10-24: across repeated samples of 100 endpoints taken five minutes apart, 30 percent successfully delivered HTTP payloads. Failed connections exhibited connection resets, EOFs, and TLS handshake failures. The list exhibits high rates of stale and unresponsive endpoints. Protocol support includes HTTP, SOCKS4, and SOCKS5 as documented in interface_detail and limits_note.
Evidence notemeasured The 2,000-row cap, the protocol split and the two payload rates were each measured from the endpoint's own output on 2026-10-24, and the measurement is what contradicts the page's 20,000+ claim. Moving up one would need a sample larger than 100 and runs spread across a day, so that a diurnal effect can be told apart from a dead list.
