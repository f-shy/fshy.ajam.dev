Free tierA market for whole 8-GPU nodes, not single GPUs. The homepage sells 'VMs, Bare Metal, & managed Slurm' and states 'Reserve the compute you need and resell what you don't'. Buying is an order on an orderbook priced in dollars per node-hour, where '1 node is 8 GPUs' and the order's count is a node count, so the smallest order the documentation shows is one node of 8 H100 or H200 cards; the smallest fill the documentation states is '1 node for 1 minute', on the resale side. SKUs are listed as 8 x H100 80GB HBM3 with 2,016 GiB memory, 1.5 TiB storage and 56 vCPUs, and 8 x H200 141GB with the same memory, storage and vCPU count. Object storage is sold at USD 0.14 per GiB-month with a 100 TiB default bucket cap, plus InfiniBand partitions, public IPv4, subnets and firewalls. The current rate is NOT published without an account: /pricing is a sign-in wall and the documented 'public' orderbook API answers 'missing authentication token' when called without a bearer token. The only rate printed on a public page is a marketing panel that shows 'Reserved price $3.00/gpu/hr' and 'Realized price $4.29/gpu/hr', with no SKU, GPU count or window attached to either figure. A second product is sold under the same name and is not behind a wall: Autoresearch publishes a rate card without a sign-in, with 'h100-1' at USD 0.084 a minute (USD 5.04 an hour) and a 15-minute idle window, an eight-GPU node at USD 40.32 an hour, batch jobs at 0.063 a minute per GPU, and 'There is no minimum charge' because billing ends when the node is stopped.
unit hours; metered on wall-clock; The Autoresearch rate card prices only H100 and CPU items, billed per minute; no A100, L40S, L4 or RTX4090 is listed on it or on the homepage.

  • volume-quota (binding) The account compute cap binds before any rate matters: compute_max_total_node_hours 5760 account-wide and 720 on one SKU, measured as the area under the allocation schedule, with a 3600-second window that does not count. At 8 GPUs a node that is 720 node-hours per SKU, and only organization verification plus a support request raises it. The second wall is the 8-GPU granularity itself, which refuses a one-GPU experiment. source
Identitycard An account, then a card for prepaid compute credits: the quickstart states 'Buying compute time charges your organization. Make sure you have credits: check with sf billing balance or top up on the dashboard'. Object storage needs a billing profile, a primary billing contact and a payment method before a bucket or access key can be created, and is invoiced monthly to the default card, 'separate from prepaid compute credits'. Raising the compute caps needs the organization verified in the dashboard and a support request. No signup was performed, so the country list and any verification step beyond organization verification are not established.
Egressnot stated on the pages read: no egress term, byte allowance or egress price appears on the homepage, the orders, limits, instances, IP-address or object-storage pages read on 2026-10-22. The only network statements are that instances reach the internet over IPv4 using TCP, UDP and ICMP, that other layer 4 protocols are blocked, and that outbound SMTP on TCP and UDP port 25 is blocked
Interfacerest, cli, s3-compatible inferred from the tooling the provider documents; not probed
Toolingdocumented first-party CLI and HTTP API: curl -fsSL https://cli.sfcompute.com | bash installs sf, sf login stores credentials, and the API is api.sfcompute.com /v2 behind Bearer tokens. Object storage is S3-compatible and the docs use rclone against it. Nothing about the CLI was installed or run here, so the commands are read, not exercised.
Composes withThe 8-GPU minimum is the whole story: there is no single-GPU lane here, and every purchase is a node for a window. The resale market is the compensating feature, because a reservation can be sold back at a limit price and the money returns as credits, which is the only way a solo buyer can commit to a long window without the idle time being pure loss. Object storage at USD 0.14 per GiB-month is expensive beside the storage topic's free tiers, so it is a place to cache a checkpoint for the length of a run, not to keep 10 TiB.
