V praxi je každá schránka založena s limitem na 120 000 zpráv, který lze opakovaně navyšovat." = unlimited mailbox size; in practice each mailbox starts with a 120,000-message limit that can be raised repeatedly (on request).   • per-object-cap (binding) per-object-cap 35 MB source
Per-object-cap 35 MB attach send from web (25 MB from mobile app), 50 MB receive per message. That is the real per-blob size. 120,000 messages/mailbox is the binding constraint (a pull-count-style ceiling on object count, raisable on request). Sending-rate limits exist but are explicitly unpublished: "Tyto limity nejsou veřejné.".
Identityemail (inferred, not read) not published
EgressUnmetered by the provider. No transfer meter is published or charged; mail is delivered by SMTP/IMAP, not metered HTTP GET. No egress pricing exists for a mailbox.
Per-object capper-object-cap 35 MB (35000000 bytes)
Interfacerest, rclone rest
ToolingNative IMAP, probe-verified live: imap.seznam.cz:993 -> * OK Seznam IMAP server ready / * CAPABILITY XLIST IMAP4rev1 AUTH=PLAIN AUTH=LOGIN AUTH=OAUTHBEARER AUTH=XOAUTH2 SASL-IR CHILDREN SORT I18NLEVEL=1 UIDPLUS ID MOVE UNSELECT. Any IMAP client or imapsync/offlineimap works. No rclone backend.
Composes withEach account is byte-unlimited (message-count-bound), so a second account carries a second allowance. 120,000 messages × the 35 MB send cap = ~4.2 TB per account before the message-count ceiling even binds; raise the count via support and the ceiling moves. Free registration, no paid tier required.
ReliabilityOperators state up front that they watch for excess use of the unlimited claim: rules are tuned to catch anyone probing "kde je ta skutečná hranice" (where the real boundary is). Message-count ceiling is enforced silently at fill time.
