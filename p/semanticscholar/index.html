Limits
  • request-rate (binding) no key: 1000 requests per second shared among all unauthenticated users, further throttled during heavy use source
  • request-rate (binding) API key: 1 request per second on all endpoints; slightly higher for some users after a review source

Bindingrequest-rate Keyless calls share one pool and the first one answered 429; a key gives a dedicated 1 request a second, and the full dataset downloads need that key too.
Identityemail Keyless calls are allowed. The key, which the full datasets also need, comes from a request form behind a CAPTCHA. The form requires first and last name, an email address, an affiliation and its website URL, and a country. It also requires private or public use, a description of 50 words or more, the endpoints and the requests per day expected. It also requires a statement that an unauthenticated request has already succeeded. The form asks for an academic or corporate email, and the vendor release notes of 2024 say requests from free email domains are no longer accepted. The form text says requests from academic and research institutions, nonprofit organizations and government entities are prioritized, and all other requests are reviewed case by case. The key is sent by email. No card. The form states a backlog of requests and gives no duration; the vendor release notes of 2024 give a backlog of about 1 month. Whether a requester who names no employer or institution is granted a key is unverified: behind a sign-up.
EgressNot metered by volume. Full dataset files are pre-signed S3 download URLs that the Datasets API hands only to a request with an API key; sample files are public.
free allowance: no byte allowance published
Per-object capAPI: batch lookup 500 paper ids and up to 10 MB a call, relevance search up to 1,000 results, bulk search up to 1,000 papers a call and 10,000,000 in all; datasets: 30 partition files each (papers in 1.5GB files, citations in 8.5GB files)
Retentionthe API is a live index; datasets are dated releases (latest 2026-10-27) with incremental diffs from one release to the next
Interfacerest REST at https://api.semanticscholar.org/graph/v1 (key in an x-api-key header); the Datasets API at https://api.semanticscholar.org/datasets/v1 lists releases with no key and returns pre-signed S3 HTTPS URLs for each partition, and the diffs between releases, only with a key
endpoint: https://api.semanticscholar.org/graph/v1/paper/search
Toolingcurl or any HTTP client; the dataset partitions are fetched by walking the list of pre-signed URLs with any HTTP downloader
Composes withThe datasets are the bulk path: release 2026-10-27 lists papers (200M records in 30 1.5GB files), citations (2.4B records in 30 8.5GB files) and s2orc_v2 full text (16M records in 30 6GB files), fetched with a key and kept current with diffs; the 1 request a second key covers lookups.
ReliabilityA keyless search on 2026-10-30 answered 429 on the first call; keys inactive for about 60 days or more may be removed, and the key form reports a backlog of requests.
NotesThe caveat is the shared keyless pool and the key gate on the full datasets. The record debrid/semantic-scholar describes the same API; this record adds the dataset bulk path and the key form. Whether a new key reaches the papers, citations and s2orc_v2 partitions is unverified: behind a sign-up. The release README says that downloading the full data requires an API key.
Evidence notedocumented The rate limits, key form and dataset sizes are vendor pages and API answers read on 2026-10-30; a keyless search answered 429 and a keyless dataset download listing answered 401. No key was requested, so the keyed rate and the time to issue a key are documented or unverified only.

Composes withThe citation graph to join against Crossref and OpenAlex metadata; the shared anonymous pool makes it a best-effort enrichment step, not a bulk harvester.

NotesThe caveat is availability, not price: a 1,000 rps global pool sounds large and behaves like a queue. A key trades the pool for a predictable 1 rps.
