Free tierFree of charge with count-based quotas and NO published byte quota: 'Personal Edition is designed for individual developers. It is in public preview and is free of charge: Image pull and push: free'. Quotas table: 'Namespace quota 3 | Public repository quota 300 | Concurrent build quota 1 | Distribution performance (pull QPS) Not guaranteed'. No storage-size limit appears anywhere in the billing or specification page. Billing is per-namespace and per-repo count, not per GB.

3 namespaces, 300 public repositories, 1 concurrent build, no pull QPS guarantee. Official guidance: 'Keep concurrent image pulls below 10.' Since 2021-10-30, more than 10 concurrent uploads/downloads is throttled. New (post-2024-09-04) personal instances list 'Public endpoints cannot be used to pull images' among their restrictions. Read that against the rate-limit guidance before betting on anonymous public pulls.
Identityanonymous (inferred, not read) not published
EgressPush and pull are billed as free for Personal Edition ('Image pull and push: free'); there is no per-GB egress line item for this edition. Enterprise Edition is the opposite. Images live in your OSS bucket and 'If you enable public network access and pull artifacts over the Internet, you are charged for outbound traffic over the Internet from OSS.'.
Interfaceoci, rclone oci
Toolingdocker/skopeo/ORAS; no dedicated rclone backend, but ORAS pushes arbitrary files as OCI artifacts.
Composes with3 namespaces x 300 public repos, x N Alibaba accounts. Because there is no byte quota, the repo count is the real ceiling, and each repo can hold many tags. Caveat: since 2024-09-04 each new Personal Edition instance is bound to one region with a dedicated endpoint, and 'Frequent image pulls trigger a TOOMANYREQUESTS error because the shared resource rate limit is reached'. Keep concurrency under 10.
ReliabilityShared multi-tenant backend; consistent TOOMANYREQUESTS under parallel pulls, and public-pull behaviour on new personal endpoints is ambiguous in the docs.
