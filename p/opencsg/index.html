Free tierNo published byte quota anywhere in the docs. And this is deliberate: the upload page states verbatim '上传大小和超时限制由站点、代理和存储配置决定' (upload size and timeout limits are determined by the site, proxy and storage configuration) and explicitly warns '不要把站点限制理解为 Git LFS 协议的统一上限' (do not read a site limit as a universal Git LFS protocol ceiling). What is measurable instead is what they actually host: the canonical deepseek-ai/DeepSeek-V3 repo is 176 files totalling 688.6 GB, of which 163 are shards above 1 GB. That is a single repo at 0.69 TB, i.e. the repo-level ceiling is at minimum ~700 GB and is shard-driven, not quota-driven.

The real limits measured live, not documented: (a) the plain resolve path is NOT the download path. Https://hub.opencsg.com/models/Qwen/Qwen3-8B/resolve/main/model-00001-of-00005.safetensors returns HTTP 200 with a 135-byte Git-LFS pointer (Content-Type: text/plain), which is exactly the round-2 'status-code theatre' trap. You must POST the LFS batch endpoint to get bytes. (b) Presigned OSS URLs carry X-Amz-Expires=259200. 72 hours, so re-resolve per request rather than caching a URL (§1b's expiring-redirect rule). (c) Per-stream shaping is severe: 2.70 MB/s on one connection (16 MiB in 6.2 s) and 1.16 MB/s on a 32 MiB pull; 8 parallel ranged GETs reached 14.49 MB/s and 15.50 MB/s across two separate tests. That is near-linear scaling (5.4x at 8 streams), i.e. it is per-connection shaping, not an aggregate cap. The same shape as Zenodo. (d) No documented upload-bytes/day cap, no retention/expiry on repos, no pull-count limit observed.
Bindingretention-clamped a clock, not a quota: bytes leave whether or not transfer is completed
Identitynational-id email + any phone + password. Docs state registration collects 'username, password, phone number, and email'. No national-ID or card requirement documented for the SaaS.
EgressFree and unmetered. Reads are served from opencsg-gitea-lfs-new.oss-cn-beijing.aliyuncs.com (Alibaba Cloud OSS, Beijing) via presigned URLs; no per-GB line, no egress meter, no bandwidth charge appears in any billing doc. The only billing surface is the AI gateway (Token spend), not bytes.
Retention(b) Presigned OSS URLs carry X-Amz-Expires=259200. 72 hours, so re-resolve per request rather than caching a URL (§1b's expiring-redirect rule). (3 days)
Interfacerest, git, rclone, cli part of the text of Free tier, above
ToolingThree real clients, all first-party: (1) git + git-lfs against https://opencsg.com/models/<ns>/<repo>.git; (2) csghub-sdk / csghub-cli (pip install csghub-sdk), with csghub-cli upload-large-folder purpose-built for multi-GB model trees; (3) a documented REST API at hub.opencsg.com/api/v1 (models, tree, branches, last_commit all return JSON). The whole platform is open source: github.com/OpenCSGs/csghub (4,071 stars) and csghub-server (1,039 stars), so the server-side quota logic is auditable. No rclone backend.
Composes withRepositories are free and unlimited per account, allowing capacity across multiple repositories without a global account cap. CSGHub includes an XNet storage backend with chunk-level deduplication and instant upload for existing blocks, reducing storage overhead for forks and versions.
ReliabilityReads depend on Alibaba OSS presigned URLs, so a URL cached for more than 72 h silently dies (301/0-byte). Resolve-then-fan-out within the window. No observed rate limit on the anonymous LFS batch endpoint. Data does not expire; repos have branches and commit history, so it is mutable rather than an archive.
