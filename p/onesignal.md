- limits note: The channel caps are audience counts (MAU, subscribers per send) rather than byte volumes, so they are filed under volume-quota, the nearest term. The rolling 15-minute application message limit is an app-disable gate filed as write-gated; the schema has no dedicated kind for a burst-disable threshold. API 429 errors throttle requests but never disable an app.
- binding note: The organization-wide 1,000 MAU ceiling is the first threshold a growing mobile push audience meets; crossing it pauses mobile push and in-app messages after a 24-hour upgrade window while web push and email continue under their own caps.
- interface detail: REST API over HTTPS with TLS 1.2 or higher on port 443 at api.onesignal.com. It creates messages, users, subscriptions, segments, Journeys and templates, and exports data as CSV. Requests authenticate with an App or Organization API key; the default response timeout is 100 seconds and exceeding a rate limit returns HTTP 429 with a Retry-After header.
- endpoint: https://api.onesignal.com
- tooling: The REST API with an App API key from Keys & IDs, callable with any HTTPS client, together with the vendor's mobile and web SDKs that register device subscriptions. The OpenAPI specification for the API is published by the vendor.
- composes with: A worker on a hosted compute service posts to POST /notifications to reach up to 1,000 organization MAU by mobile push or web push to at most 10,000 subscribers per send, and Event Streams or webhooks forward delivery events to an external destination.
- reliability: Above 1,000 MAU, mobile push and in-app messages stop sending until upgrade; the organization is re-enabled 30 days after deleting active mobile subscriptions and staying under the cap. An app is temporarily disabled when delivered messages exceed 10 times its subscription count in a rolling 15-minute window. Self-serve accounts are disabled after three failed payment attempts.
