Per-object-cap: GitHub's 100 MiB repo block is the real ceiling (50 MB proven). commit-ref must be used for permanence; branch refs are re-fetched within minutes. HTML is gated behind an interstitial confirmation page. Irrelevant for blobs, fatal if you need to serve HTML.
Identityemail email
EgressFree, no account, no key. Cloudflare-fronted with permanent per-URL caching on the tag/commit form.
Per-object capper-object-cap: GitHub's 100 MiB (104857600 bytes)
Interfacerest rest
ToolingTwo URL forms: raw.githack.com/<owner>/<repo>/<branch|tag>/<path> (development, minutes of cache) and rawcdn.githack.com/<owner>/<repo>/<tag|commit>/<path> (production, cached permanently). Plain GET.
Composes withServes GitHub files at 50 MB where jsDelivr's /gh/ stops at 20 MB. That is the single most useful number here, because it doubles the shard size on an otherwise identical origin. Use rawcdn.githack.com for immutable shards and jsDelivr /gh/ as a second mirror for the smaller ones.
ReliabilitySmall independent operator. Its own homepage says it serves 479M+ requests and 46 TB+ of traffic monthly, which is ~0.2% of the 1 TiB/day requirement, so treat it as a mirror, never the primary. A branch-ref URL 301s to raw.githubusercontent.com (i.e. it silently stops being a CDN and bills GitHub instead).
