Free tierNO QUOTA ANYWHERE IN THE SERVER. There is no quota code, no quota column in the DB migrations, and no quota endpoint. Because the feature does not exist. A contributor filed Feature Request #334 '(Feature Request) Disable uploads when less than X GB of storage is available', still Open 5 months later, precisely because an admin cannot cap anything. Storage is whatever the instance's disks hold: OSM-FR alone reports 22.7M pictures = 48.5 TB of originals + 22.5 TB of derivates.
unit GB; metered on stored-bytes

Identityemail Email. But indirectly. /api/configuration on OSM-FR literally returns "registration_is_open": true and /api/auth/login 302s to openstreetmap.org/oauth2/authorize; the OSM signup form (/user/new) accepts user[email] + user[display_name] + password, no affiliation, no .edu, no review, email-confirm only. IGN instance uses its own Keycloak (panoramax.ign.fr/oauth/realms/geovisio). Eithe….
EgressUnmetered and CDN-friendly: no auth on any GET, plain nginx serving, Accept-Ranges honored. Verified 206 Partial Content with Content-Range: bytes 0-1023/3336348 on a live HD original.
Interfacerest, cli REST + OGC API Features + STAC 1.0 + STAC item-search. POST /api/upload_sets → POST /api/upload_sets/{id}/files → POST /api/upload_sets/{id}/complete. Bearer token from POST /api/auth/tokens/generate.
Toolingpanoramax_cli (v1.4.1, Windows/Linux binaries + Python lib) with upload, download, transfer, migration subcommands; Docker panoramax/api; JOSM/iD plugins; the CLI can also transfer sequences between instances, so one file can be replicated across the whole federation.
Composes withUpload once → replicate to N instances with panoramax_cli transfer → each instance serves its own /images/<2/2/2/2>/<uuid>.jpg path → front the whole federation with Cloudflare. Since every picture is addressed by a stable UUID and every asset URL is in the STAC item's assets.hd.href, a proxy can rewrite to whichever instance is alive.
ReliabilityVolunteer hardware with ZFS RAIDZ2 + daily remote snapshots; no SLA and no capacity guard, so an instance can silently fill and start 500ing on upload. That is the whole reason #334 exists.
