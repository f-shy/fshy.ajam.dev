Free tierNo data-volume limit. A 2025 peer-reviewed comparison of Zenodo and ScienceDB in Journal of Agricultural Big Data states it plainly: for ScienceDB the 数据大小 row reads '没有数据量的限制，用户可以上传任意大小的数据集' (no limit on data volume; users may upload datasets of any size), against Zenodo's 'max 50 GB, can be raised to 200 GB in one step'. Datasets above 2,000 files or above 1 TB are merely flagged 'restricted' pending an email. A negotiable ceiling, not a hard one.

Write-gated by 'formal review' (形式审核) of upload completeness, accessibility and the data-availability statement. Light-touch but still a human queue. Every dataset must have a subject category from the PRC GB/T 13745-2009 classification and at least three keywords. Metadata is mandatory and detailed (data generation procedure, temporal/spatial scope, per-file description). Some submission flows route through a CAS email or CSD account, which for the foreign client means using the GitHub/ORCID button rather than the native form.
Identityemail email
EgressFree, anonymous for public datasets. DOI resolution works (302 to the dataset page).
Interfaceftp web + ftp
ToolingExplicitly two upload paths: '浏览器在线上传和FTP客户端在线上传'. Browser and FTP client. FTP is the one that matters at TB scale and is unusual among research repositories. There is also an Open API and OAI-PMH listed in the help centre. Login accepts a native account or third-party GitHub / ORCID / CAS / WeChat. And the English help page lists GitHub explicitly, which is the route that avoids Chinese identity requirements entirely.
Composes withUnlimited datasets per account with no per-user aggregate cap, so capacity is datasets × a negotiable per-dataset ceiling. FTP ingest means an unattended rclone or lftp job.
ReliabilityPublic JSON endpoints differ from Zenodo conventions. Specific API download paths returned HTTP 404 on 2026-10-21 while dataset web pages resolved normally. Following DOI redirects (/detail?dataSetId=...) provides the standard path to download assets.
