Limits
  • per-object-cap (binding) largest single file that you can upload to a product is 20 GB source
Per-object-cap 20 GB (products >$0.99) / 250 MB cumulative (priced $0). 'Download all' button only appears under 500 MB total content, but a single ZIP sidesteps that. Repo shows MAX_EPUB_READER_ARCHIVE_SIZE = 32 MB and thumbnail cap 5 MB. Those are feature caps, not the product-file cap.
Identityemail an email address and a password, or a Google or X sign-in, on the signup form. No card and no phone number appear on that form, and uploading files needs no payout profile; withdrawing sales runs a Stripe identity check that asks for a date of birth, phone number and possibly a government ID.
EgressCloudFront in front of S3 (confirmed in their open-source repo: CLOUDFRONT_* + FILE_DOWNLOAD_DISTRIBUTION_URL_PROD). No per-download quota published.
Per-object caplargest single file that you can upload to a product is 20 GB (20000000000 bytes)
Interfacerest Web + documented REST API (products, product_files); the codebase is open source (antiwork/gumroad), so limits are inspectable.
ToolingREST API with access token; the repo exposes /attachments/... presigned paths via SignedUrlHelper.
Composes withThe $0.99 pricing gate is the mechanism: price at $1, get 20 GB/file, unlimited files per product, unlimited products. A $1 product that never sells still costs the seller ~nothing after fees. 20 GB x N files.
ReliabilityPurchases require a payment method on the seller side to withdraw, but uploading does not. Download URLs are presigned CloudFront/S3 and short-lived, so there is no stable hot-link. Archive/delivery tier only.
