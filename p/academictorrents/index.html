per-object-cap: 10 MB for the .torrent file only; no cap on the dataset it describes. retention: entries are permanent in practice; the PDF describes a network designed for durability across node failure. request-rate: not documented on the API page. There is no seed guarantee - 'as long as at least one person can become a seed for that data' - so durability is a function of who else mirrors it.
Identityemail sign-up asks a desired username, an email address and a password twice and sends a confirmation email; it asks no phone number and no card, and an educational institution address enables more features but is not required
EgressFree, and structurally so - it is BitTorrent, so egress is other peers' bandwidth. Also offers an HTTP fallback: 'Backup URLs (also called WebSeeds)' are injected into the .torrent so the swarm can be skipped entirely. Their own docs note most free hosts (Google Drive, Dropbox) do NOT work as webseeds because they lack RANGE support, while archive.org and Zenodo (single-file only) do.

Interfacerest rest
ToolingREST v2 at https://academictorrents.com/apiv2/ - POST /apiv2/entry with file as a base64-encoded .torrent and urllist as the webseed URLs; API key required. Also POST /apiv2/collection. A first-party uploader exists (github.com/academictorrents/academictorrents_uploader) and a mirroring.md doc for running a Smart Node that seeds selected collections from an RSS feed. Standard BitTorrent clients (transmission-daemon recommended) do the actual transfer.
Composes withThis is a discovery and swarm-coordination layer, not storage. What it multiplies is availability: one .torrent entry (10 MB) makes an arbitrarily large dataset reachable through unlimited peers, and the webseed lists let you point at storage you already have elsewhere (archive.org items, Zenodo records, your own HTTP server). Chain shape: bytes live on IA/Zenodo/your server -> webseed URL -> AT entry -> swarm plus HTTP fallback. Verified that the mechanism is real: a fetched .torrent carries url-list with https://files.inria.fr/ and the AT announce URL.
ReliabilityThe fatal caveat: without a donor node or a webseed, an entry is a pointer to nothing. Their model is explicitly 'the burden of hosting data' distributed to volunteers, so AT gives zero storage guarantee. It is also not a place to put bytes - upload.php returned 409 and there is no bulk endpoint. Treat it as a distribution amplifier for data that already has a home, never as a home.
