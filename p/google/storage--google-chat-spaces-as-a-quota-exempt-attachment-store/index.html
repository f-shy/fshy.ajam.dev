200 MB per file hard cap; some file types blocked; 600 media.upload/min/project and 3,000 media.download/min/project; requires a Google Workspace account + Cloud project + Chat API enabled (personal @gmail.com accounts are not a supported developer surface; Chat API auth doc requires Workspace). Chat API quotas are per-minute only. The docs state 'no limit to the number of requests you can make per day' if you stay under them.
Identityinstitution The upload guide's prerequisite is a Business or Enterprise Google Workspace account with access to Google Chat. Payment details were not seen; no sign-up was entered.
Egressmedia.download is limited to 3,000 attachment reads per 60 seconds per project; it supports the Range header for partial downloads. The Chat API pages read state no per-GB egress price and no byte quota.
Per-object cap200 MB per file (200000000 bytes)
RetentionAdmin-controlled: a Vault retention rule for Chat can discard messages after a retention period of 1 to 36,500 days, or keep them indefinitely.
Interfacerest rest
ToolingREST over HTTPS: media download is GET https://chat.googleapis.com/v1/media/{resourceName=**}; the upload guide calls media.upload, then creates a message that attaches the file. No rclone backend is named on the pages read.
Composes withWrites are bounded by 600 media.upload calls per 60 seconds per project. The limits page states no per-day request limit while the per-minute quotas are respected. Whether quotas multiply across projects is not stated on the pages read.
ReliabilityMessages/attachments live in a space. Deleting or archiving the space, or removing the app from it, can orphan the data; no documented retention guarantee. Blocked MIME types must be avoided.
NotesPer-record unlimited: 200 MB per attachment, and Chat messages AND attachments explicitly do NOT count toward Google storage quota. 600 attachment uploads/min/project x 200 MB = ~120 GB/min theoretical ingest.
