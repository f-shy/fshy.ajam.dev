200 MB per file hard cap; some file types blocked; 600 media.upload/min/project and 3,000 media.download/min/project; requires a Google Workspace account + Cloud project + Chat API enabled (personal @gmail.com accounts are not a supported developer surface; Chat API auth doc requires Workspace). Chat API quotas are per-minute only. The docs state 'no limit to the number of requests you can make per day' if you stay under them.
Identityinstitution (inferred, not read) not published
EgressNot metered. Downloaded through Chat API media.download (3,000 attachment reads/min/project), supports Range requests. No per-GB charge in the docs.
Per-object cap200 MB per file (200000000 bytes)
Interfacerest, rclone rest
ToolingOfficial Chat API with service-account (app) auth; media.upload for write, GET /v1/media/{name}?alt=media for read with Range. No dedicated rclone backend exists. This is a build-it-yourself REST store; google-api-* client libs cover both directions.
Composes withUnlimited messages x 200 MB per attachment. 20 attachments per interactive message on web, but the API path is per-media-upload, so the binding constraint is the 600 uploads/min/project rate, and projects are multiplicative (30-project default quota per user). Storage is free because Chat attachments are quota-exempt. This is the strongest multiplier in the Google stack.
ReliabilityMessages/attachments live in a space. Deleting or archiving the space, or removing the app from it, can orphan the data; no documented retention guarantee. Blocked MIME types must be avoided.
