per-object-cap 200 MB or 500,000 words. Notebook cap is per-user; source cap is per-notebook; 'sharing a notebook does not change the source limit for any collaborator'. Copy-protected PDFs are rejected outright. Consumer API is undocumented and Google has changed enforced limits without updating the published tables.
Identityemail a Google Account: the plans page states 'Sign up free of charge by using your gmail account', and the help centre requires verifying age in that Google Account before access. No card appears in that flow; whether a phone number is asked for was not read.
EgressNo egress metering or fee anywhere in the product. Reads happen through Google's own UI/API, not a CDN URL.
Per-object capper-object-cap 200 MB (200000000 bytes)
Interfacerest, cli No official public API for consumer accounts. Working path is the reverse-engineered internal batchexecute API: notebooklm-py (19,838 stars, pushed 2026-10-21) exposes Python, CLI, MCP server, and a local REST server; notebooklm-mcp (202) and notebooklm-rest-api (91) wrap it.
Toolingpip install notebooklm-py; notebooklm source add, notebooklm ask, notebooklm generate, notebooklm download. Google Cloud has a separate documented Enterprise API (notebooks.sources.uploadFile) that requires a Workspace/Cloud entitlement.
Composes with100 notebooks x 50 x 200 MB = 1 TB per Google account. Google accounts are free and email-only, so N accounts linearise. Upskilling to Plus/Pro only raises the per-notebook source cap (100/300), so the notebook count stays at 200/500. The free tier already gives the widest notebook multiplier per dollar.
ReliabilitySource files cannot be downloaded in original binary format. The platform retains static extracted text and exports plain text or image conversions rather than bit-exact files. Ingestion provides 1 TB of document indexing subject to API rate limits.
