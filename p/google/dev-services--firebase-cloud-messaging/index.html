Free tierCloud Messaging (FCM) is listed as No-cost on both the no-cost Spark plan and the pay-as-you-go Blaze plan; the pricing plans page says full usage of no-cost Firebase products at no charge even with several million users, and no per-message price or monthly message-count allowance is stated
unit unlimited; metered on none; The counted unit is a message sent downstream. There is no stated per-message charge or monthly message cap. Sending is governed by a per-minute rate quota, not a free allowance. The unit vocabulary has no term for messages, so the absence of a count cap is recorded as unlimited; the true unit is messages per minute.

Limits
  • request-rate (binding) default quota of 600k downstream messages per minute per project; above it the API answers HTTP 429 RESOURCE_EXHAUSTED until the quota refills the following minute source
  • request-rate (binding) for Android, at most 240 messages per minute and 5,000 messages per hour to a single device source
  • request-rate (binding) collapsible messages limited to a burst of 20 messages per app per device, with a refill of 1 message every 3 minutes source
  • per-object-cap 4096 bytes maximum message payload (2048 bytes for messages to a topic) source
  • retention-clamped message time to live at most 4 weeks (2,419,200 seconds), the default when unset, with ttl 0 discarding an undeliverable message source
The downstream quota measures messages, not requests; HTTP client errors 400-499 (excluding 429) count against it, and quota minutes are not aligned to the clock. A self-service increase of up to 25 percent can be requested once usage is regularly at least 80 percent of quota for 5 consecutive minutes a day with a client error ratio below 5 percent; temporary increases above 18M messages per minute need at least 30 days notice, at most 2 events a year. A maximum of 4 collapse keys is allowed at any given time. The documented limits are subject to change.
Bindingrequest-rate FCM has no per-message charge or monthly message cap, so the default downstream rate quota of 600k messages per minute per project is the first constraint a growing sender meets; the per-device rate and the 4096-byte payload cap bind a single target sooner but not the account.
Identityemail Access is through a Google Account. The Firebase console sign-in page shows Use your Google Account with an Email or phone identifier field and a Create account link, behind a CAPTCHA. No card is asked at sign-in, and the no-cost Spark plan needs no payment method; a Cloud Billing account with a payment method is required only for the Blaze plan's paid services, which FCM messaging does not need. Sending through the HTTP v1 API from a non-Google server needs a service account JSON file from the Firebase project.
Egressnot applicable: a push messaging transport with no per-message, byte or bandwidth line; the pricing table lists Cloud Messaging as No-cost, and an app server posts JSON to the HTTP v1 API while Google delivers to the device
Per-object cap4096 bytes maximum payload for both notification messages and data messages, except sends from the Firebase console composer, which enforces a 1000 character limit; a message sent to a topic is limited to 2048 bytes (4096 bytes)
RetentionAn undelivered message is held in FCM storage for its time to live, at most 4 weeks (2,419,200 seconds), which is also the default when the field is not set; setting ttl to 0 discards a message that cannot be delivered immediately (28 days)
Interfacerest The FCM HTTP v1 API takes an HTTP POST to https://fcm.googleapis.com/v1/TARGET_PROJECT_ID/messages:send with a JSON message body, authorized with a service account JSON file, Application Default Credentials or a short-lived OAuth 2.0 access token. The Firebase Admin SDK wraps the same send operation. Clients receive messages through platform SDKs for iOS, Android and web; the console Notifications composer sends without code.
endpoint: https://fcm.googleapis.com/v1/projects/PROJECT_ID/messages:send
ToolingFirebase Admin SDK for Node.js, Java, Python, Go and C#; the FCM HTTP v1 REST API with a service account key or Application Default Credentials; the Firebase CLI; client SDKs for iOS, Android, Web, Flutter, Unity and C++; and the console Notifications composer.
Composes withA worker on any host sends one HTTPS POST to the FCM HTTP v1 API to reach devices by registration token, topic or condition on iOS, Android and web; delivery through FCM is no-cost while the sender's own backend is billed on its own terms.
ReliabilityDelivery is best effort and a message ID means accepted, not delivered; the connection is encrypted but not end-to-end encrypted. Over-quota or overload sends answer HTTP 429, and the limits are subject to change. For an Android device with direct channel messaging that has not connected to FCM for more than one month, FCM accepts a message then immediately discards it.
NotesCloud Messaging is no-cost on both the Spark and Blaze plans, so one record covers the offer. Revisit when the pricing page adds a per-message charge, when the default downstream quota changes, or when the message types page changes the payload cap. A send path needs Firebase project credentials, so no probe was run and the rung stays documented. The docs page firebase.google.com/docs/cloud-messaging/concept-options answered HTTP 404; the retention value is instead taken from the REST reference, which states the same 4-week maximum and default. The schema has no unit for messages, so the free tier unit is recorded as unlimited and the true unit is named in free_tier.notes.
