per-image: 200 MP resolution ceiling, landscape orientation, EXIF GPS + timestamp required. Read side: graph.mapillary.com 50,000 requests/minute/app; tiles.mapillary.com 50,000 requests/DAY. The forum thread 'Can and does someone replicate the Mapillary images database?' states outright that the free plan's 50,000-image limit blocks bulk re-download.
Bindingrequest-rate calls are bounded rather than bytes, which is fatal to a nightly job on a monthly counter
Identityemail an account is needed to upload images, use the API, and download data
EgressMapillary is 100% free to use—for any use case!
Per-object capwe've set an upper limit of 200 MP to image resolution and 110GB for video file-sizes
Interfacegraph, cli Graph API at graph.mapillary.com (images, map features, detections); upload via mapillary_tools CLI or Desktop Uploader
Toolingmapillary_tools (pip), Mapillary Desktop Uploader, official Python SDK, MapillaryJS
Composes withWrites are geographically anchored, so this is a corpus, not a bucket. Read path returns tile/thumb URLs; a normal CDN in front works, but origin fetch is token-gated.
ReliabilityUploads are unmetered, while bulk retrieval is rate-limited to 50,000 vector tile requests per day via API.
