Free tierKeyless and anonymous: a public instance takes GET /search?q=...&format=json with no key or account. Each instance is run by its own operator and listed on searx.space. JSON output is off by default (search.formats lists html only) and an operator must enable it. Asked a scripted format=json query on 2026-10-31, none of 20 listed instances returned results: 14 answered 429 Too Many Requests, 3 a bot-challenge page, 1 a 418 cookie-setting script, 1 a 403 and 1 a redirect to its front page; a plain query without format=json returned no results from any of the 20 either (16 answered 429, 3 a bot-challenge page, 1 a 418).

Toolingcurl or any HTTP client: GET or POST /search with q and format=json, no key. A plain scripted request is refused before any result is returned, for example by the SearXNG limiter with 429 Too Many Requests (its bot detection classes a request as a bot when Accept-Language is unset, Accept lacks text/html or the User-Agent matches a bot list that includes curl, wget and python-requests), by an instance that has not enabled json with 403, or by a bot-challenge page in front of the instance, from Anubis or Substation, that needs JavaScript.
Composes withPublic instances do not chain as a scripted search source, since every listed instance probed on 2026-10-31 answered a scripted query with 429, 403, 418, a redirect or a bot-challenge page; scripted search goes to the hosted search APIs of this topic (for example crawler-scraper/tavily, crawler-scraper/exa and crawler-scraper/youdotcom), and a self-run SearXNG instance with the json format enabled is the last resort.
ReliabilityOn 2026-10-31, 20 listed instances were asked a scripted json query and none returned results: 14 answered 429 Too Many Requests, the default refusal of SearXNG's bot detection, 3 a bot-challenge page, 1 a 403, 1 a 418 cookie-setting script and 1 a redirect to its front page.
