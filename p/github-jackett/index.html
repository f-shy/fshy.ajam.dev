The binding constraint is the machine: an instance needs a process that stays up, which means a free compute service rather than local hardware. Trackers marked 'invite needed' in the indexer list 'have no active maintainer and may be broken'.
Bindingrequest-rate The upstream trackers' own rate limits pass straight through, and the instance's cache is the only thing that reduces how often they are hit.
Identityanonymous Jackett itself needs no account. Individual indexers may need one, and the README marks some as invite-only with no active maintainer.

Interfacerest Torznab and TorrentPotato over HTTP at the instance's own address: /api/v2.0/indexers/all/results/torznab/api?apikey=...&t=search&q=...
endpoint: http://127.0.0.1:9117/api/v2.0/indexers/all/results/torznab/api
ToolingA container or a .NET runtime on a free compute instance; Sonarr, Radarr and Prowlarr speak the same Torznab. FlareSolverr is integrated for Cloudflare-walled indexers.
Composes withOne Torznab endpoint in front of every tracker already accessible, which turns a dozen scrapers into one URL that the automation stack and a debrid cache check both use.
ReliabilityCloudflare-walled indexers fail without FlareSolverr, and the README warns that invite-only entries may be broken; a client that only runs Jackett gets partial coverage and does not know which indexer failed unless it reads the dashboard.
Notes'public torrent-search API behind Jackett' is really a private Torznab fan-out: Jackett adds no index of its own, it translates scrapers. The nearest hosted equivalent is TorrentClaw's Torznab endpoint, which needs a key and is PRO-gated.
