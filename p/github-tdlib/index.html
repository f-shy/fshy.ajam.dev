Limits
  • per-object-cap (binding) 2000 MB per upload in --local mode (50 MB on api.telegram.org) source
  • write-gated requires api_id and api_hash from my.telegram.org source
Download has no size limit in local mode; upload does. The asymmetry is the reason a mirror bot can pull a 2 GB file but still split anything above 2 GB.
Bindingper-object-cap At 1 TiB/month this still fails first: no object above 2000 MB can be sent, so the month is 512+ objects at best. Flood control is nowhere near binding (see telegram-uploadbot).
Identityany-phone my.telegram.org issues api_id/api_hash to a Telegram account, and a Telegram account is registered to a phone number. No card and no email are required for the app registration.
EgressNo separate charge from Telegram. The host's outbound bandwidth is the part that is metered, by whoever runs the host.
free allowance: none published
Per-object capIn local mode the server 'Upload[s] files up to 2000 MB' and 'Download[s] files without a size limit.'
RetentionNot applicable: a gateway. Bytes live in the chat they were sent to, not on the server.
Interfacerest HTTP JSON API. 'By default the Telegram Bot API server is launched on the port 8081, which can be changed using the option --http-port.' The server 'accepts only HTTP requests, so a TLS termination proxy needs to be used to handle remote HTTPS requests.'
endpoint: http://127.0.0.1:8081 (default --http-port)
ToolingDocker image or CMake build of tdlib/telegram-bot-api; any Bot API client library can be pointed at it. The state-of-the-art in-the-wild user is the Torrs bot, which runs the server to lift its own 50 MB ceiling.
Composes withRaises a bot from 50 MB per upload and 20 MB per download to 2000 MB and unlimited, so a 2 GB file in a channel becomes retrievable by a script; needs a VM plus a TLS proxy, which a free compute tier supplies.
ReliabilityOne server per bot at a time: moving a bot requires logOut from api.telegram.org first, or updates are silently lost ('If the bot is logged in on more than one server simultaneously, there is no guarantee that it will receive all updates.').
NotesAbandon this if Telegram ships the local-mode upload cap below 2 GB, or if the 2000 MB figure disappears from the README without a replacement. This is software that must be run locally, not a hosted service; it is recorded because it is the only documented way to make a bot a 2 GB path, and because hosted leech bots visibly depend on it.
Evidence notedocumented The limit sentences are on the project README and the Bot API page, both read. A measured rung needs a 2 GB upload through a running instance; that was not done.
