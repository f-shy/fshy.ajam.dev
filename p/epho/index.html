A run is metered from boot to teardown and stops when the run does; one live turn per chat.
Bindingvolume-quota The USD 10 starting credit is the first allowance to run out; the five-turn active limit is a concurrency gate that queues rather than stops work.
Identityemail (placeholder) A team API key is required and, per a third-party review, sign-up involves email verification. The exact fields of the registration form were not read: the app.epho.io registration page redirected to sign-in and presented a login wall to every reader.
EgressNot published as a volume or price; the sandbox runs on the vendor's boxes and artifacts return as presigned URLs.
Per-object capnot applicable: the unit is a sandbox, not an object
RetentionA chat's sandbox stops when a turn ends and resumes for the next one; files and agent session survive. Artifact download URLs are presigned for about ten minutes and renewable.
Interfacerest, chat One REST endpoint POST /api/v1/chat plus /chat/async, streaming server-sent events and a chat_id for a durable multi-turn sandbox; MCP servers and repository tokens are declared in the request.
endpoint: https://app.epho.io/api
ToolingA single HTTP POST with a JSON body and an API key; no SDK or daemon is required.
Composes withRuns can be driven from scripts, CI, cron or a Slack bot, and model tokens bill to the caller's own provider key with no Epho markup.
ReliabilityA dropped stream does not kill a run: events are persisted and replayed on reconnect; the platform re-queues a run on a fallback sandbox backend when a box dies mid-run.
