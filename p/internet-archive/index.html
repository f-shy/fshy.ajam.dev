1 TB/item hard, 500 GB/item recommended; 500-700 GB single-file ceiling; 5,000 files/day across all items (zip counts as 1); recommended <=10,000 files/item but API accepts 250,000; DELETE bucket not allowed; S3 Range headers ignored; only HTTP/1.1 REST, no ACLs; every upload enters a per-item catalog queue plus a global derive queue that can block writes (503-slowdown-spam). Use x-archive-queue-derive:0 to skip expensive derivation.
Identityemail A free archive.org account asks for an email address, a screen name and a password, with a reCAPTCHA at sign-up; uploads need that account signed in, and IAS3 keys are generated at archive.org/account/s3.php from the same account.
EgressUnmetered and free: every file in every item is a world-readable HTTP URL (https://archive.org/download/<id>/<file>) with no auth and no egress bill; IAS3 doc states "ACLs are fake. permissions are: World readable, Item uploader writable." Every public item additionally gets an _archive.torrent with IA webseeding as a second free distribution path.
Per-object cap1 TB/item (1000000000000 bytes)
Interfaces3-compatible, rest, rclone, cli part of the text of Limits, above
ToolingIAS3 = S3-compatible REST (PUT = create item, multipart, x-archive-auto-make-bucket, x-archive-queue-derive:0, x-archive-size-hint); rclone backend 'internetarchive' (Tier 3, added v1.59, github.com/rclone/rclone 60.4k stars); official CLI/Python 'ia' github.com/jjjake/internetarchive (1,923 stars, pushed 2026-10-20); Rust client github.com/LucaCappelletti94/internetarchive-rs. S3 keys from archive.org/account/s3.php.
Composes withSupports unlimited items per account with up to 1 TB per item across multiple accounts. Archives can package small files into zip archives to align with item-based transfer limits.
ReliabilityWrites are asynchronous through a per-item queue; the global derive queue can stall uploads and deletes for hours during backlogs, and large/high-file-count items time out and fail to derive. Items are permanent (no TTL) but nothing is guaranteed private.
Notes1 TB hard limit per item page ("Currently, there is a 1TB size limit for item pages"), recommended 500 GB / 1,000 files per item; items per account unlimited. Single file "should not be larger than ~500 to ~700 GB".
