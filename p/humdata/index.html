Free tierNo published per-user or per-file quota anywhere in the docs. The platform hosts the files itself ('upload the data file directly to the HDX platform'), S3-backed. Aggregate catalog is 28,359 datasets and growing at organisational pace.

Limits
  • write-gated (binding) reviewed by OCHA source
  • write-gated (binding) approval, not identity or payment source
write-gated: you must belong to an HDX organisation with publishing rights. Any registered user may REQUEST a new organisation (/org/request/new) and the request is human-reviewed by OCHA. So the gate is editorial approval, not identity or payment.
Identityemail email
EgressUnmetered public download. Direct GET on /dataset/<slug>/resource/<id>/download/<file>; no egress counter, no rate card, no CDN token. Files are anonymous to read. No login to download.
Interfaceunknown CKAN 2.x action API (package_search / package_create / resource_create) plus the hdx-python-api wrapper, which is the documented write path.
Toolingcurl + API token, or pip install hdx-python-api. Write operations need an API token from the user profile; token is per-user, free, issued on signup.
Composes withCKAN resource_create accepts a URL as well as a local file, so HDX can act as a metadata+mirror layer over another host. Public download URLs are stable and content-addressable by resource id. Reasonable as a serving tier.
ReliabilityUN-operated, 10+ years of uptime, but editorial review means a rejection is silent and unbounded. No SLA on org approval, and an org can be removed for content outside humanitarian scope. Do not treat as primary durable storage.
