Free tierN/A. DataLad is a wrapper over git-annex; quota is the special remote's. Its value here is that it makes 'dataset + N special remotes + reproducible publish' a supported, documented workflow instead of hand-written annex commands.
unit mixed; metered on unstated
Pricenone stated
Identityanonymous no account for the software: the user installs and runs DataLad and git-annex 10.20230802 or later from PyPI. The walk-through's worked target is an S3 bucket on an AWS account, and the page states that AWS signup wants an email address, a physical address and a credit card before verification, plus a GitHub account for the metadata sibling. DataLad itself asks for no card and no phone number; the card belongs to the S3 account the walk-through demonstrates.
EgressInherited; DataLad's S3 walkthrough specifically configures publicurl so consumers clone the git metadata from GitHub and stream file content from the bucket with no credentials.
Interfaces3, git, cli s3
Toolingdatalad CLI (Python), datalad create-sibling-s3, datalad push --to <sibling>, datalad get. Requires git-annex >= 10.20230802 for S3 publicurl on post-April-2023 buckets.
Composes withDataLad dataset hierarchy of superdatasets and subdatasets partitions large archives across independently-served subdatasets with individual remotes. Command datalad siblings distributes logical datasets across multiple S3 accounts while preserving git history.
ReliabilityUsed in production by academic consortia (OpenNeuro etc.) precisely for multi-TB datasets on donated storage. The most battle-tested 'big dataset on free/cheap stores' pattern that exists.
