Free tier10,000 messages per month free per account, shared across all the account's applications; a message is one successful API delivery to one user regardless of device count. Receiving on each client platform is free for a 30-day trial, then a USD 4.99 one-time per-platform license is required to keep receiving.
unit requests; metered on request-count; The headline unit is a message. One message is a successful messages API call to one user regardless of the number of devices on that account; a delivery-group message counts once per user in the group. Since May 1st the 10,000 allowance is a pool shared by all applications on an account, with no cap on the number of applications. Pushover for Teams has a 25,000 messages per month free pool. The monthly pool resets at 00:00:00 Central Time on the 1st of the month.

Limits
  • volume-quota (binding) 10,000 messages per month free per account, shared across all applications source
  • request-rate A 429 HTTP status code once the message limit is reached, until the first of the next month source
  • per-object-cap One image attachment up to 5,242,880 bytes (5.0 MB) per message; message body up to 1024 UTF-8 characters source
  • retention-clamped Unverified messages deleted after 21 days; delivered messages deleted on device sync; optional ttl in seconds source
  • per-ip-shaping No more than 2 concurrent HTTP requests; an IP sending many failed 4xx requests is temporarily blocked source
A single request addresses at most 50 comma-separated user keys. A device name may be at most 25 characters. Emergency priority retries are at least 30 seconds apart, expire at most 10800 seconds and are capped at 50 retries. An account may register at most 10 devices it owns or primarily operates. The vocabulary has no kind for a recipient-count cap, so the 50-user cap is recorded in limits_note.
Bindingvolume-quota The 10,000-messages-per-month account pool is the first constraint a sender meets; it is shared by all applications and resets monthly, so a burst of alerts exhausts it before the per-object cap or the concurrency guidance matters.
Identityemail The web signup form asks for an E-Mail Address and a Password (with a confirmation field, at least 8 characters) and an hCaptcha verification; no phone number and no card are requested at registration. A user key is e-mailed on signup and shown on the dashboard, and an application API token is obtained by registering an application, a free process. To keep receiving after the 30-day trial a USD 4.99 one-time per-platform license is bought in the app or with a card or PayPal, but that purchase is not a registration requirement and was not performed.
EgressNot a byte-metering offer: the vendor delivers notifications to its own clients through Apple and Google push gateways, and the pricing page states no per-notification or per-byte price. Sending 10,000 messages a month is free; a 429 answer applies above the free pool.
free allowance: 10,000 messages per month per account
Per-object capMessages are limited to 1024 UTF-8 characters (up to 4 bytes each), with a title of up to 250 characters; supplementary URLs up to 512 characters and URL titles up to 100 characters. Each message may include one image attachment of at most 5,242,880 bytes (5.0 megabytes). (5242880 bytes)
RetentionA delivered message is deleted from the Pushover servers once a device confirms delivery over HTTPS; unverified messages are deleted after 21 days. Messages are stored on each device separately and are not viewable from the Pushover website or other devices unless also pushed to them. A ttl parameter sets a positive number of seconds after which the message is deleted from the devices it was delivered to. (21 days)
Interfacerest, browser A versioned REST API: POST https://api.pushover.net/1/messages.json with token, user and message parameters, form-encoded or JSON over HTTPS; a .xml suffix returns XML. A GET to /1/apps/limits.json returns the account limit, remaining and reset. A separate e-mail gateway turns e-mail to a per-user @pomail.net address into notifications. Receiving is through the vendor's own iOS, Android and desktop browser clients; the service cannot push to third-party apps.
endpoint: https://api.pushover.net/1/messages.json
ToolingAny HTTP client that posts form-encoded or JSON over HTTPS, including curl; official and third-party libraries in many languages. A recipient runs a Pushover client app on an iOS, Android or desktop device and supplies a user key; a sender registers an application to obtain a 30-character API token.
Composes withA scheduled job or monitoring script on a free host posts one HTTPS request to the message API to reach a device; a subscription URL lets end users opt in to a delivery group without sharing their user keys.
ReliabilityAbove the monthly pool all applications on the account receive a 429 and stop sending until the reset or a capacity upgrade. The API advises no more than 2 concurrent HTTP connections and temporarily blocks an IP that sends many failing 4xx requests. Temporary server problems answer 5xx, after which a retry no sooner than 5 seconds is advised.
NotesPushover is a hosted service; receiving needs the vendor's own client apps and a per-platform license after a 30-day trial, while sending through the API has a 10,000-messages-per-month free pool per account. The free pool is the headline offer recorded here; the post-trial receiving license is a separate cost named in free_tier.notes and identity_cost. The vocabulary has no kind for a recipient-count cap, so the 50-user-per-request cap is in limits_note. Revisit when the pricing page changes the free sending pool or the per-platform license price.
