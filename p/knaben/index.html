Limits
  • request-rate (binding) no number published; the v2 docs justify the rewrite with 'we've been struggling to serve the amount of bandwidth from the server to all the API clients' and close with 'if you alone are the main reason the server CPU sits at 100%, I will hunt you down'. Measured: 10 sequential GETs over about 24 s all 200, and 6 concurrent GETs all 200 source
v2 moved from POST to GET so the edge can cache the responses, which is a bandwidth measure rather than a per-client quota. The 300-result ceiling is the only hard number, and six concurrent requests drew no 429.
Bindingrequest-rate The operator names CPU and bandwidth as the failure mode and refuses to publish a number, so voluntary restraint is the only limit; no byte quota exists on this side.
Identityanonymous No key, no account, no captcha on the GET requests made today.
Egressno byte allowance: the API returns JSON records and magnets
free allowance: none published
Per-object capnot applicable: results are metadata and magnets
Retentionthe database keeps documents after they go dead; the docs say 1.7 million documents were seen in the last week and the 'dead' flag is opt-in
Interfacerest GET /v2/search and GET /v2/browse with query parameters (q, sf, c, t, o, d, s, f, xxx, unsafe, dead, seen); size maximum 300. v1 still exists as POST /v1 with a JSON body. There is also an RSS page at knaben.org/rss/.
endpoint: https://api.knaben.org/v2/search?q=ubuntu&s=2
ToolingOne GET. Sonarr/Radarr-style clients reach it through Torznab proxies; TorrentClaw lists Knaben as one of its sources, so the API is already the feed behind another index.
Composes withQuery by title, take the magnetUrl or hash, hand the hash to a debrid service's cache check, and only fetch the ones that come back cached.
ReliabilityBandwidth pressure is stated by the operator, and the API answers are edge-cached (Cache-Control public with s-maxage 300), so a stale page can show a torrent that has since gone dead.
NotesThe best machine-readable torrent feed in the sector that needs nothing: no key, documented parameters, 300 results per call, and a magnet in every hit that carries a hash. Its weakness is exactly the thing the sector asks about: the vendor publishes no rate, only a threat.
