Free tier'JDownloader is a free, open-source download management tool with a huge community that makes downloading as easy and fast as it should be.' The software and its hoster/decrypter plugins are free; what it needs is a machine with Java and disk space.
unit unlimited; metered on none; No hosted first-party instance exists. The vendor offers desktop installers for Windows, Linux and macOS plus a multi-OS JAR, and every remote path points back at a JD installation the caller runs.
PriceUSD 0
Limits
  • request-rate core caps simultaneous connections per file at 20; board staff describe raising it with domain rules source
  • write-gated captchas and host wait timers must be solved per download unless a premium account is attached source
Every cap that matters is imposed by the target host, not by JD. The tool adds a 20-connection ceiling per file and a default concurrency limit.
Bindingnone No JD-side quota binds at 1 TiB/month; the host's free-tier limits and the absence of a local machine bind first. Public instances exist but are private containers behind credentials (see evidence), so they are not a route.
Identityanonymous No account needed to install and use JDownloader. A MyJDownloader account is optional and only needed for remote control. The support FAQ states: 'Do I need to register an account to use JDownloader? No! You only need an account when you use MyJDownloader which is completely optional!'
EgressThe transfer runs between the JD host and the file host. JD meters nothing and resells nothing.
free allowance: none: no service-side bytes
Per-object capnot applicable to the tool: the largest object is whatever the target host serves. JD writes to local disk, so the practical cap is the device's free space.
Retentionnot applicable: JD downloads to local storage it does not own. Nothing is retained server-side.
Interfacecli, rest GUI and headless (jar) modes; a Click'n'Load listener on port 9666 that accepts container posts from a browser; and a 'Deprecated API' the MyJD docs say can be enabled in Advanced Options to bypass the connection server and reach JD directly.
ToolingFirst-party installers and JAR; MyJDownloader for remote control; Docker images by third parties (jlesage/docker-jdownloader-2, junkerderprovinz/jdownloader) that expose the GUI over VNC in a browser. A wrapper needs a machine to install on, which is not available.
Composes withJD is the decrypter layer of last resort: one tool covers roughly a hundred hosters and several hundred container/decrypter plugins, so it composes with any storage or debrid service that hands it links.
ReliabilityPublic web instances found in the wild are other people's containers: one answered HTTP 200 with a 'Credentials needed' gate, one answered 530, one 502. They are not a service, they disappear without notice, and using one puts the links on a stranger's disk.
NotesThis is the tool the debrid question is usually answered with, and it fails on the install requirement. The three public instances were found by search and probed as ordinary web pages; no login was attempted on any of them. Their existence shows the pattern (docker + KasmVNC + credentials), not a public service.
Evidence notedocumented The vendor page, the board thread and three probes are in hand. A measured rung needs a JD install downloading a real link, which needs a machine that is not available.

Free tierRegistration is free and the free account is usable: 'The Customer is required to register on AppWork's website in order to use the Service. The Customer can use the Service for free after registration, which does not incur a fee. AppWork shall only offer a limited scope of Service to the Customer who uses the website for free.' No device count, call count or byte quota is published anywhere on the site.
unit unlimited; metered on none; The free tier's scope is described only as 'limited' and the paid packages that expand it are not priced on any public page reached today. The unit field says 'unlimited' because nothing is metered in bytes; it does not mean unlimited devices, which is unpublished.
PriceUSD 0
Limits
  • request-rate connection server answers 429 TOO_MANY_REQUESTS, 503 OVERLOAD and 503 MAINTENANCE; no published call budget source
  • write-gated account registration plus email confirmation: 401 ERROR_EMAIL_NOT_CONFIRMED is an API error type source
The free tier's 'limited scope' is never enumerated. Features for free users can be added, changed or withdrawn at any time ('Ein Anspruch auf die Zusatzfunktionen hat der Kunde jedoch nicht').
Bindingnone Nothing in the seven-kind vocabulary fails at 1 TiB/month because no bytes cross this service: a JDownloader device does the transfer on its own connection. What fails first is architectural, not a quota: a running JD instance must be supplied, and the free tier's feature set is unpublished.
Identityemail Self-registration on the website, free. The API document exposes /captcha/getCaptcha and an account-registration route, and lists ERROR_EMAIL_NOT_CONFIRMED and EMAIL_FORBIDDEN as server errors, so a working email address is the gate.
EgressNo file egress: the service carries API calls and link lists between the web UI/apps and the customer's JDownloader device. Terms section 2(1) defines the service as access to 'the computer program JDownloader ... installed on a computer of the Customer'.
free allowance: none: no byte path
Per-object capnot applicable: MyJDownloader relays control commands and link lists to a JDownloader installation that the customer runs. No file passes through AppWork's servers.
Retentionnot applicable: no file storage. Downloads land on the storage attached to the JDownloader device.
Interfacerest REST over HTTPS at https://api.jdownloader.org; the API document states 'The API is REST based, but currently only GET and POST routes are offered'. Every call carries a request id and an HMAC-SHA256 signature built from the AES-CBC session tokens; email must be lower case.
endpoint: https://api.jdownloader.org
Toolingmyjdapi (Python), the official Android/iOS apps and browser extensions, and third-party clients over the same API. A wrapper must implement AES128-CBC key exchange plus HMAC-SHA256 per call, so the barrier is the signing handshake, not a missing client.
Composes withOne MyJD account drives any JDownloader device that can be started elsewhere (a free VM), which removes the local machine from the path but not the requirement that some machine runs JD.
ReliabilityFree accounts have no availability guarantee (terms: 95% monthly availability is promised only for paid packages). The connection server returns 429/503 under load, and the docs warn that results syntax 'MAY CHANGE'.
NotesDoes not answer the debrid question by itself: it resolves links only through a JDownloader installation the caller provides. The device count the requirements asks for is not published; the only device statement found is that the dashboard lists connected devices and the Android app 'manage multiple JDownloaders'. Two public JDownloader web instances were probed as part of the jdownloader record and neither accepted anonymous input.
Evidence notedocumented Read: the English terms section and the API basics document, both live today, plus a probe of the API host. A measured rung needs a signed /my/connect plus a real device; that was not attempted.
