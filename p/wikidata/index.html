Free tierReads need no account and no key. Wikimedia API limits are per minute: 10 requests for an unidentified client, 200 for an unauthenticated client with a compliant User-Agent, 200 for a new account and 2000 for an established editor. The Wikidata Query Service allows 60 seconds of processing per 60 seconds per User-Agent and IP. The whole graph is a weekly JSON dump; latest-all.json.bz2 is 103,565,615,653 bytes.
unit requests; metered on request-count; The per-minute limits are new in 2026 and stated to be subject to experimentation and change. A compliant User-Agent carries contact information. Accounts with a bot flag are exempt. The query service at query.wikidata.org holds the main graph; scholarly-article items are in a separate service at query-scholarly.wikidata.org. Daily incremental dumps carry the last 24 hours of additions.

Limits
  • request-rate (binding) 10 requests per minute for an unidentified client, identified by nothing but its IP address source
  • request-rate (binding) 200 requests per minute for an unauthenticated client with a compliant User-Agent, and for a new account; 2000 per minute for an established editor source
  • request-rate (binding) Wikidata Query Service: 60 seconds of processing time per 60 seconds per User-Agent and IP, 30 error queries per minute, 5 parallel queries per IP source
  • per-ip-shaping dump downloads rate limited and capped at 3 connections per IP; one connection read 16,777,216 bytes in 5501.7 ms source
  • request-rate (binding) 200 requests per minute for a User-Agent that carries a contact URL: the 201st request in a minute answered 429 with a Retry-After header, on the Action API and on the REST API
  • request-rate (binding) a User-Agent that names no contact, with the Action API and the REST API counted together: each source address was answered 200 for its first 10 requests in a minute and 429 after, so requests that left from four source addresses were answered 429 from the 41st
  • request-rate (binding) Wikidata Query Service: no per-minute request ceiling was met; 50 parallel queries with a User-Agent that names no contact, and 250 queries within one minute with a User-Agent that carries a contact URL, all answered 200, although the manual gives 5 parallel queries per IP
Every SPARQL query has a hard 60-second deadline. A client that keeps sending past a 429 can be temporarily banned from the query service. The rate-limit page asks for 3 or fewer concurrent requests. Fifteen parallel REST reads sent with a User-Agent that names no contact answered 13 times 200 and twice 404, with no 429. A request with a generic library User-Agent (python-requests) answered 403 with a request to set a User-Agent, and 30 such parallel reads all answered 403. The per-minute ceilings are enforced by the REST gateway, an Envoy rate-limit service that keeps its counters in Redis, on the Action API and the REST API; the rate-limit FAQ says the request limits currently apply to those two APIs, and the query service is throttled by processing time instead. The gateway counts requests whose User-Agent names no contact per source address and requests whose User-Agent carries a contact per contact string. A 429 from the gateway carries Retry-After, the header x-envoy-ratelimited and the text "You are making too many requests to the API."
Bindingrequest-rate An unidentified client gets 10 requests per minute and a compliant User-Agent 200, so a whole-graph read goes to the weekly dump, which is shaped per IP rather than counted.
Identityanonymous No account and no key for the APIs or the dumps: the query service and the REST API answered 200 to requests sent without an account. A descriptive User-Agent is required in practice: a generic library User-Agent answered 403. A User-Agent with contact information moves a client from the 10 to the 200 requests-per-minute class; an account adds rate only for an established editor (2000 per minute) or an account with a bot flag (exempt).
EgressFree, with no byte price; dump downloads are rate limited and capped at 3 connections per IP, and a client without an informative User-Agent may be blocked without notice
free allowance: no byte allowance published
Per-object capa SPARQL query stops at a hard 60-second deadline; the Action API returns entities in groups of up to 50 per request; the full JSON dump is one 103,565,615,653-byte bz2 file read with HTTP ranges
Retentionthe entity-dump index listed dated directories from 20260914 to 20261028 on 2026-10-30; older RDF and JSON dumps from April 20, 2015 on are kept on the Internet Archive
Interfacerest, graphql SPARQL over HTTP GET or POST at https://query.wikidata.org/sparql (the vocabulary has no SPARQL term, so it is filed under rest), the Wikibase REST API, the MediaWiki Action API, the Wikibase GraphQL API, and dumps over HTTPS with Range support: JSON, Turtle and N-Triples (all and truthy), lexemes, and daily incremental dumps.
endpoint: https://query.wikidata.org/sparql
ToolingAny HTTP client that sends a descriptive User-Agent; SPARQL clients against the query service; JSON dump readers named on the download page (qwikidata and simple-wikidata-db in Python, wd2sql in Rust, JsonDumpReader in PHP); lbzip2 for the parallel-compressed bz2 dumps.
Composes withThe weekly JSON dump is the bulk path for a whole-graph read and the per-minute APIs answer targeted lookups; the Wikimedia Enterprise free account (50,000 on-demand requests and 30 snapshot requests a month, no card) is a second, keyed bulk route to the same data.
ReliabilityThe 2026 per-minute limits are stated to be subject to change; a client that ignores 429 answers can be temporarily banned, and a request with a generic library User-Agent answered 403 at once.
NotesCaveat: an unidentified client is held to 10 requests per minute, and the per-minute classes are new in 2026. The JSON and RDF entity dumps are stable interfaces; the XML dumps are not, and the XML dumps of all wikis are deprecated with a January 2027 sunset.
Evidence notemeasured The per-minute ceilings are read: requests whose User-Agent carries a contact URL were answered 429 from the 201st request in a minute on the Action API and on the REST API, and requests whose User-Agent names no contact were answered 429 after the first 10 requests from each source address, so from the 41st when the requests left from four source addresses; the query service answered 200 to all 250 queries sent in one minute. The read path was probed: the SPARQL endpoint and the REST API answered 200 with no account, the JSON dump answered a HEAD with its size and a 206 to a 16 MiB range, and reads with a generic library User-Agent answered 403. The 200 per minute of a new account and the 2000 of an established editor were not read: unverified: behind a sign-up.
