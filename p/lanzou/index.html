Bindingper-object-cap The total is genuinely unlimited and the egress is genuinely free, so nothing about capacity or traffic binds. 100 MB per object over a 10 TiB working set is 105,000 objects, which makes the file count the problem before the bytes.
Identitycountry-phone the register form (pc.woozooo.com, terms on accounts.woozooo.com) asks for 手机号 plus an SMS code, then a username and password; it shows no email field and no country selector. A foreign-number path is unverified: behind a sign-up
EgressFree and explicitly unmetered: '下载不限速度，不限流量，不限次数，免登录下载'. The free product is ad-funded and the FAQ states 我们对下载速度不做任何限制
free allowance: unlimited
Per-object cap100 MB per file on the free tier: '不限空间大小，不限下载速度，只是限制文件大小，最大不超过100M/个文件' (100000000 bytes)
Retentionunverified: the vendor home page as read states no share-link lifetime; account retention is not published
Interfacerest
Toolingno official API. Reverse-engineered clients mount it: the OpenList Lanzou driver in account, cookie or link mode, and a mature unofficial Python wrapper, zaxtyson/LanZouCloud-API, which does login, list, upload, download, delete, move, folder operations and direct-link extraction, and whose README claims it works around both the file-type and the per-file size limits by splitting
Composes withUnlimited total times 100 MB per object is the pure per-record-unlimited shape: 20 TiB is about 210,000 objects, all inside one free account's allowance. The gate is that registration is SMS-only on a mainland number
ReliabilityDomains rotate across lanzou.com, lanzoue, lanzouj, lanzoux, and lanzoul. Share links valid on one domain frequently return HTTP 404 on others, requiring automated tools to maintain a multi-domain fallback list. CDN delivery exhibits geographical routing instability.
NotesExemplifies the per-item unlimited storage model where the 100 MiB per-file upload cap is the primary operational constraint. Vendor documentation confirms unlimited overall account capacity with per-file restrictions.
