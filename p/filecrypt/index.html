Free tierOpening a container costs nothing and needs no account: a container URL answers 200 to an anonymous GET. Creating one is offered on a public Create page ('You can also create a test container containing any link you want here https://filecrypt.cc/Create.html'). The site root redirects an anonymous visitor to /Login.html, which is the management side of the service, not the container side.
unit unlimited; metered on none; No price list, no quota page and no account requirement were found on the container path.

  • request-rate no published limit; the anonymous container page returned 200 with a language selector and no link list, indicating links are produced client-side or require additional steps source
The captcha is per container, not per account, so it cannot be paid away. Cloudflare fronts the whole site and the root response carries a challenge-platform signature.
Bindingwrite-gated The captcha on a protected container is what stops an unattended wrapper first; account quotas do not exist on this path, and a container holds links rather than bytes so no volume quota applies.
Identityanonymous No account was needed to fetch a container page or to reach the Create page. The /Login.html redirect applies to account management.
EgressNo egress of its own: the container page lists links to other hosts and the browser or downloader fetches from those hosts.
free allowance: none: no service-side bytes
Per-object capnot applicable: a container holds links, not bytes. The size shown on a container page is the sum of the linked host files.
Retentionunverified: no page states how long a container survives. Containers dated 2024-2025 still appear in search results with live host links, so retention is at least months for popular containers, but no policy is published.
Interfaceunknown HTML container pages. The machine interfaces are Click'n'Load (a page script POSTs the link list to a local JDownloader listener on 127.0.0.1:9666) and the DLC container file offered on the page. No documented JSON API for resolving a container was found, so a wrapper parses the page.
ToolingJDownloader's filecrypt plugin is the mature client; the board records that its direct-link parsing broke in 2024 while CNL and DLC kept working. A HTTP wrapper is feasible because the container page is server-rendered HTML.
Composes withA container is the index, not the storage: resolving it yields one link per host, and those links are what a debrid service, a leech site or a JD instance consumes. It composes with every other row among debrid providers.
ReliabilityContainers rot when the underlying host files are removed: pages show an online count (e.g. '4/13 Online') so dead links are visible. Cloudflare challenges and per-container captchas break unattended resolution.
NotesThe container page is the only part of debrid that answers 'resolve a link with no install and no account' cleanly: it turns one protected URL into the host list. It does not produce a direct file link, and it does not bypass the host's own limits. Relevant because DDL posts increasingly wrap their mirrors in a container rather than printing five host URLs, so any pipeline that scrapes DDL indexes needs a container resolver as a second stage. Not the storage topic's: the container holds no bytes.
Evidence notedocumented Two container probes and the root probe are measured; the captcha and creating-without-account statements come from pages and a third-party issue comment. Solving a captcha and diffing the resolved list would raise this to measured.
