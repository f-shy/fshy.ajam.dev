Per-object capFiles above 1.9 GB are split into 7-Zip volumes because 'the self-hosted Bot API server limit is 2 GB per file'.
RetentionWhatever the chat keeps; the project caches by Telegram file_id so a repeat request re-sends instead of re-downloading.
Interfacerest, cli A Telegram chat in front of TorrServer, plus a CLI-style configuration; lossless FLAC needs a second, user-account (MTProto) session because the Bot API only accepts .mp3/.m4a audio.
ToolingDocker or source, TorrServer, and the tdlib Bot API server for the >50 MB path; 7-Zip is mandatory for objects above 1.9 GB.
Composes withThe reference implementation of the whole lane: a torrent leeched on somebody else's VM, uploaded to Telegram through a local Bot API server, split at 1.9 GB, and re-sent by file_id on request.
ReliabilityA ban risk the project acknowledges in its own README; a self-run stack also means the Bot API server must be moved with logOut or updates are lost.
NotesSoftware, not hosted. It is the only source found that states the 50 MB -> 2 GB -> 1.9 GB-split chain in one place, which makes it the best independent confirmation of the platform caps among debrid providers. Abandon if the README's limit table changes.
