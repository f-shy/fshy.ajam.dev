Free tierA free tier exists but its allowance is not published in the API documentation. The API types accounts explicitly - 'accountType: 0 = Free, 1 = Premium, 2 = Lifetime premium' and 'premiumLeft: Number of seconds remaining for premium status, always 0 for free users' - and the site describes itself as 'Premium link generator and Seedbox, partially free'. The daily quota exists as error codes maxLink ('Daily link limit reached') and maxData ('Daily data limit reached'), with no number attached anywhere in the reference.
unit none; metered on downloaded-bytes; unit 'none' means no allowance is stated, not that the tier is empty: free accounts get keys and a daily budget whose size the vendor does not write down.
PriceEUR 4.00 per 30 days, flat; EUR 3.00 for 15 days; 9, 16 and 25 EUR tiers listed with durations not readable in the rendered page

The throttle is one hour, not one minute, and it is per endpoint rather than per account. A retry loop that re-hammers the same endpoint converts a short burst into an hour of downtime, which is the failure mode a naive exponential backoff still walks into.
Bindingvolume-quota The daily data meter on the account is what ends a monthly transfer of 1 TiB on a free key; the request rate only bites when a user polls a single endpoint, and its penalty is an hour rather than a minute.
Identityemail Email only for a free account, which is issued an API key; premium needs a payment method. The API key page is https://debrid-link.com/webapp/apikey.
EgressNo byte allowance published. Two account-level daily meters are enforced instead: maxData and maxDataHost ('Daily data limit reached' and 'for this host'), plus maxLink and maxLinkHost for link counts.
free allowance: not published
Per-object capnot applicable to unrestrict. Torrent size is capped with 'torrentTooBig - The torrent is too big or have too many files', with no number published.
RetentionCloud files live under /files/{idParent}/list until deleted; torrents live in the seedbox list. No expiry is published for either.
Interfacerest REST v2 at https://debrid-link.com/api/v2/ (host also answers as debrid-link.fr), authenticated with a private API key from /webapp/apikey or with an OAuth2 access_token; v1 additionally supported a timestamped X-DL-TOKEN/X-DL-SIGN/X-DL-TS signature scheme. OAuth2 device-code and auth-code flows are documented at /api_doc/v2/oauth2-device-code and /oauth2-auth-code. No WebDAV or filesystem interface was found in the method list.
endpoint: https://debrid-link.com/api/v2/
Toolingrdt-client and Decypharr both support it for *arr; Torrentio supports it for Stremio; there is a community MCP server and zurg nightlies add a backend. No rclone backend of its own.
Composes withThe one API here whose documentation is itself a machine-readable JSON endpoint (/api/v2/api_doc/infos plus /api_doc/errors), which means a client can generate its own bindings and refresh them without scraping; pair it with Decypharr for *arr.
ReliabilityThe documentation site is a JavaScript application: both docs.debrid-link.com and the rendered /api_doc/v2/* pages return an empty shell to a plain reader, and /api_doc/v2/introduction returns 200 with the body replaced by 'Loading ...'. Only the JSON endpoints behind it carry the text.
NotesThe self-description 'partially free' plus the existence of maxLink/maxData is as far as the evidence goes on the free tier; do not confuse that with a published quota. Trigger condition: if /api/v2/api_doc/infos ever carries a limits block, replace the 'unpublished' fields with numbers. The vendor's own two pages give 41 and 42 hosts; the record keeps 41, which is the number on the page a buyer reads. There is no annual plan: the ladder stops at 300 days for 25 EUR. The free tier is real but undocumented in public, which is itself the finding: a reader cannot know what it buys without creating an account. The premium page says 41 hosts and the live API lists 43, so the marketing count lags the API. No host in the live list carries isFree:true, while the vendor's own documentation sample does - the free-host set appears to have been emptied. A textbook case of a stable price hiding a shrinking product: the euro figure is byte-identical across 37 months while the host count falls 173 -> 164 -> 53 -> 41, a 76% loss. Any table that compares this service by price alone ranks it first and is wrong. Classified as undetermined in the matrix because the vendor checkout could not be read. The reseller route is real and vendor-published, which is enough to say a cardless account can buy it, but not enough to say the vendor takes crypto. Potential failure points: the flood refusal, the 20-slot ceiling, or a per-host daily quota. The flood refusal is the only one with a stated duration and the only one treated as an hour-long park. The vendor's own error table could not be read, which is the main gap in this record. Technically the best-shaped small debrid for automation, and the one whose retention is least documented. Trigger condition: if no retention statement appears by the future review, keep the null and stop asking; a WebDAV listing after a lapse is the only route that answers it.
