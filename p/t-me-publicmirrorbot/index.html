The 80 GB figure is generous for a free bot and is the only hard number the operator publishes. Nothing is said about how many tasks may run at once, which is where a shared public bot actually queues.
Bindingper-object-cap At 1 TiB a month the link ceiling is what stops a single transfer: 80 GB is about 12 links to the monthly target, so a 1 TiB archive has to be split. The daily count is explicitly unlimited, so it cannot bind.
Identityany-phone A Telegram account is the only gate: any phone number that can receive the signup code. No email, payment or identity document is asked for by the bot.
EgressThe bot pulls from a remote URL and re-serves it: a mirror returns a link on the operator's host, a leech returns the file into the chat. No bandwidth figure or price is published.
free allowance: unlimited daily link count
Per-object cap80 GB per link on every mode: mirror, leech, yt-dlp and MEGA. (85899345920 bytes)
RetentionNot stated. A mirror lands in operator storage and a leech lands in the user's Telegram; no expiry is published for either.
Interfaceunknown A Telegram bot, not an HTTP service: the control channel is Telegram chat with @publicmirrorbot, and there is no documented REST endpoint. The bot's preview names a fallback bot and a support group rather than an API.
ToolingTelegram client only. Automating it means driving a Telegram user session, which is a real constraint for a client that wants a script rather than a chat window.
Composes withA resolver for links a normal client cannot fetch: a MEGA or yt-dlp URL goes in, a direct file comes out, and it bypasses the per-host limits a downloader would otherwise meet. It is the human-shaped version of what a debrid subscription does, with an 80 GB per-link ceiling instead of a monthly one.
ReliabilityA shared public bot with no SLA, with limits published in a channel post rather than on a stable web page. The channel listing includes a beta fallback bot.
NotesClassified as a service because it resolves and fetches remote URLs rather than mirroring an account: a user hands it a URL and gets bytes back. The account-mirror bots in the same ledger were not recorded, because they only drive somebody's own cloud account.
Evidence notereported The limits are the vendor's own post in the bot's linked updates channel, not a vendor specification page, and nothing was transferred. Moving to documented needs the numbers on a stable page; moving to measured needs one 80 GB job run and read.
